# spec_render.md — Рендер-пайплайн: мир, свет, атмосфера, перф-правила

> Код: `render_world.js`, `render_light.js`, `render_scan.js`, `visions.js`/`render_visions.js`,
> `render_glitch.js`. Палитра глубины `_STRATA` — в `spec_world.md`. Юнит — `spec_unit.md`.

## ⚠️ Перф-правила Canvas2D (выстраданы замерами)

- **Глобальный бюджет кадра (нагрев GPU)**: главный цикл `game.loop` КАПИТ частоту до `FPS_CAP`=60
  (на 120/144Гц-дисплеях не жечь GPU вдвое; rAF планируется В НАЧАЛЕ цикла, ранний пропуск тика — без
  рисовки; игра кадрово-независима — скорости берут `dt`). DPR канваса капится до `DPR_CAP`=1.75 в
  `resize` (на retina dpr=2 бэкстор был 4МП → ~3.1МП, −23% пикселей). Замер: CPU `drawScene` ~1.5мс
  (дёшево) — грел именно растр 4МП×120fps во ВСЕХ режимах (вкл. статичное меню). Итог 60fps×3.1МП ≈
  −62% растровой работы. Самый дорогой GPU-узел кадра — тень тоннеля (`render_world.drawTunnelShadow`:
  `drawImage` офскрина с `shadowBlur≈TILE` каждый кадр); присуща визуалу, смягчена капом FPS.
- **Пауза/троттлинг в ФОНЕ (`game.loop`, `_schedule`)**: rAF браузер тормозит ТОЛЬКО для скрытой
  вкладки; «окно ВИДИМО, но не в фокусе» (другое приложение сверху) он гонит на полной частоте → GPU
  грелся «в фоне». Лечение: `visibilitychange` → скрыто = ПОЛНАЯ пауза (loop не перепланирует rAF, при
  возврате — `_schedule` + сброс `last`); `blur`/`focus` → не в фокусе кап падает до `BG_FPS`=24 (≈ −60%
  кадров). `_rafPending` гарантирует один кадр в полёте (нет двойных цепочек при гонке событий).
  ⚠️ В превью-iframe это значит: без фокуса игра идёт на 24fps (eval-правки видны с задержкой ~42мс) —
  буди фокусом/скриншотом. Редактор рига (`tools/rig_editor.html`) — тот же приём + ЛЕНИВАЯ перерисовка:
  в фокусе без анимации (`playing&&!noAnim` / `ikPreview` выкл) и без взаимодействия (`_edDirty`) `draw()`
  НЕ зовётся (0 GPU в простое); взаимодействие/анимация ставят dirty.
- **DOM-оверлеи (мета `meta_dom`, кодекс `codex_dom`) — отдельный путь от canvas-цикла!** Их БЕСКОНЕЧНЫЕ
  CSS-анимации (мета: `.pcb-flow` «ток по проводам»; кодекс: `.spin-slow/.spin-rev` кольца, `.seg-pulse`,
  `.newdot`) крутит компоновщик GPU — `game.loop`-пауза их НЕ касается, и при «видимо, но не в фокусе»
  браузер их не тормозит. Лечение: `game._syncIdle()` (те же blur/focus/visibility) вешает на `<html>`
  класс `bg-idle` → CSS-правило `html.bg-idle <overlay> * { animation-play-state:paused }`. Сами экраны
  закрыты = `display:none` (анимаций нет), так что в обычной игре они не греют — только пока ОТКРЫТЫ.
  Любую НОВУЮ бесконечную CSS-анимацию в оверлее это правило-`*` гасит автоматически.
- **НЕТ `ctx.filter` (blur) на пути кадра** — десятки мс/кадр (глифы давали 57мс). Допустим только
  на маленьком КЭШИРОВАННОМ офскрине (render_light: гало конуса).
- **НЕТ паттерна «офскрин → drawImage» для сложных форм каждый кадр** — GPU-столл ~30мс
  (видения-монстр давали именно это). Рисуй прямо на canvas: форма стоит ~0.004мс.
- Мягкость без blur: overscale-ореол + 2-tap + edge-fade; сканлайны — кэш-паттерн (1 fillRect).
- `getImageData` для профилирования НЕнадёжен (форсит GPU-sync, раздувает числа) — мерить
  CPU-команды + код-ревью.

## Порядок слоёв кадра (game.drawScene)

фон `PAL.pit` → `drawWorld` (порода/жилы/трещины/валуны-тайлы/маркеры/ассет города) →
`drawServers` → `drawEnemies` → `drawLoot` → **`drawDust`** → **`drawFalling`** (обвалы/валуны В МИРЕ, ПОД
туманом — видны только в зримом/освещённом) → [не-debug:] `drawFog` → `drawHeadlight` →
`drawBackdrops` (поверх тумана, клип по воздуху) → `drawVisions` (под юнитом) → тени-трубы/юнит: клип-видимый-воздух → `drawTentacles` →
`drawRingUnit`/`drawTachikoma` → `drawScanFx`/`drawEnemyScanFx`/`drawBackdropScan` → `drawFx` →
`drawCity`(виджет) → `drawBigHint` → HUD → `drawInterference` (помехи, поверх всего).

## Пыль (dust.js / render_dust.js)

Косметические частицы (логика `Dust`, рендер `drawDust`), рисуются В МИРЕ **до тумана/света** → в
незримом/неосвещённом естественно гаснут (это и есть «только где видит игрок»). Два «материала»:
- **КРОШКА** (`grit` + редкий `pebble` по `DUST_PEBBLE_P`) — грубые частицы, обычная гравитация `DUST_GRAV`,
  быстро падают. Цвет: крошка светлая `PAL.bone`, камушек тёмный `PAL.ash` (страта-тон сливался с породой).
- **ПЫЛЬ** (`fine`) — ЛЁГКАЯ ДЫМКА: слабый разгон `DUST_FINE_GRAV` с ТЕРМИНАЛЬНОЙ скоростью `DUST_FINE_VT`
  (медленно оседает → зависает) + боковой синус-дрейф `DUST_FINE_SWAY`, долго живёт. Рендер — НЕ точки, а
  мягкий КЛУБ: один КЭШИРОВАННЫЙ радиальный спрайт (`_dustPuffSprite`, тон `bone`, создан ОДИН раз) →
  per-частица `drawImage` со scale (растёт по жизни = дисперсия) + альфа-фейд. `size` — БАЗОВЫЙ диаметр клуба.

Источники: **Бурение дефолт-буром** (`drill`, пока `unit.drilling`) — крошка с грани блока В СТОРОНУ юнита (`wrapDeltaPx`
по кольцу) + мелкая пыль ВМЕСТЕ, темп `DUST_DRILL_DT`. **Автономные винтовые щиты** (`borerDrill(dt,b)`, пока `b.drilling`) —
ТА ЖЕ крошка+пыль у ФРЕЗЫ щита, летит НАЗАД (против хода) + гравитация; таймер на щите (`b._dustT`) → щиты сыплют независимо;
зовётся в `game.loop` per-борер. (Плюс `burst` на пробитии тайла — уже был у щита.) **Фон** (`ambient`) — РЕДКО (`DUST_AMBIENT_DT`×рандом),
ищет в видимом окне камеры воздух ПОД породой («потолок») → РАНДОМНО крошка / пыль-струйка / вместе (осыпь
как в штольне). Потолок `DUST_MAX`=200 частиц; дёшево: крошка `fillRect`, пыль — `drawImage` КЭШИРОВАННОГО
клуб-спрайта (градиент сделан ОДИН раз, НЕ офскрин-на-кадр — перф-правило соблюдено), пик ~50 при бурении.
Только в `playing` → под фоновой пауза-кэпом.

## Удар-искры (effects.js `Fx.hit` / render_fx.js `drawFx`)

Фидбэк урона (референс — искры от обстрела брони): при падении hp юнита/врага/структуры `game._hitFxPass`
зовёт `fx.hit(px, py, color, n, dir)`, где `dir` — unit-вектор ЛИНИИ ОГНЯ (источник→жертва, из `_hitAwayDir`
по ближайшей угрозе; игра не хранит откуда прилетело). Модель разлёта (в `hit`): при известном `dir` —
**ПУЧОК-рикошет** из ДВУХ групп: ~55% **ВДОЛЬ огня** (тугой быстрый джет, малая гравитация, короткий ttl) +
остальные **ВВЕРХ** (подброс `-90°`±наклон по горизонт. стороне огня, сильная гравитация → дуга вниз). Без
`dir` — быстрый круговой разлёт. Флаг `hot` (≈55%) → бело-раскалённое ядро. Скорости `TILE·3–6.6`, ttl `0.11–0.32`.
Рендер `drawFx` (kind `spark`) — **КОМЕТА** аддитивом (`'lighter'`): тусклый широкий хвост (цвет источника, назад
по скорости, длина ∝ скорости·`a`) + короткое яркое ядро к голове (бело у `hot`) + раскалённая голова-точка.
Цвета по цели (`HIT_SPARK_*` штук): юнит `#ff5040`, враг `#ffd070`, структура `#ff9a4a`. ⚠️ перф: только
`stroke`/`arc`, без `ctx.filter`/`shadowBlur`/офскрина; частицы истекают за ~0.2–0.3с (десятки на пике).

## Мир (render_world.js)

- **Кладка**: тёмный раствор + куски-булыжники размером ∝ плотности; цвета из `_strat(y)`
  (см. spec_world). Трещины по `tile.dig` — паутина на каждом осколке, проступает от стороны
  входа бура. `INDESTRUCT` — тёмная плита-основание (банты сверху/снизу), но даёт силуэт тени.
- **Рваная кромка — НЕ по сетке**: `_ragDepth(along, side)` в долях тайла — ОСТРЫЕ зубцы
  (высокочастотный value-шум на ЛИНЕЙНОЙ интерполяции `_ragLin` — углы, не волны), мин. глубина
  убирает плоские участки; чистая функция мировой координаты → бесшовно у соседей, без «защипов».
  `raggedTeethRects` заливает полосу от кромки тайла внутрь породы до зубчатой линии;
  `_appendTeeth` — тот же контур без beginPath/fill (для общих путей).
  ⚠️ **ПЕРЕКРЫТИЕ ПРОТЁКШЕЙ ПОРОДЫ** (drawWorld, после `drawChunks`): base-fill и чанки рисуются `TILE+1` →
  залезают на 1px ВПРАВО/ВНИЗ в соседний воздушный тайл, а `raggedEdge` красит дно ТОЛЬКО ВНУТРИ породы (в
  воздух не достаёт) → на дробном `scale` этот 1px виден как «полоска породы» РОВНО по квадратной кромке тайла
  (и H, и V, всегда, даже в природных пещерах). Лечится перерисовкой дна воздуха (`backColor`, тот же `TILE+1`)
  ПОВЕРХ осколков, ДО `raggedEdge` → квадратная кромка невидима, остаётся только рваная эрозийная линия.
- **ОДИН профиль кромки кормит всё**: видимую кромку, силуэт тени (`drawTunnelShadow` — офскрин,
  destination-out, shadowBlur внутрь хода) и КЛИП СВЕТА (`render_light._coneSolid` читает тот же
  `_ragDepth`). Менять профиль — только синхронно.
- `clipVisibleAir(ctx,world,camera)` — клип по ВИДИМОМУ воздуху (прямоугольники воздуха +
  эрозийные каймы со стороны воздуха): щупальца/юнит рисуются только внутри → за породой скрыты,
  окклюзия по той же кромке, что и мир. ⚠️ **`drawTunnelShadow` клипит тень ТОЖЕ по `clipVisibleAir`, НЕ
  по квадратам тайлов**: квадратный клип оставлял эрозийную КАЙМУ (визуально воздух, но не квадрат-тайл) БЕЗ
  тени → на границе тайла светлая кайма рядом с тёмным воздухом = квадратный ШОВ (светлый-слева/тёмный-справа,
  прерывистый — глубина каймы пляшет с зубцами). С `clipVisibleAir` тень идёт ровно от рваного края вглубь хода.
  ⚠️ **WINDING-инвариант клипа**: прямоугольники воздуха в `clipVisibleAir` — `rect(sx,sy,TILE,TILE)`, БЕЗ
  `+1`. С `+1` rect залезал на 1px ВПРАВО/ВНИЗ в кайму породы; зубцы стороны 2 (ПРАВАЯ стена, `_appendTeeth`)
  намотаны ОБРАТНО относительно rect → в зоне перекрытия `[кромка..+1px]` winding гасится в 0 (nonzero-rule) →
  ДЫРА в клипе ровно на кромке → тень туда не попадала → тонкая СВЕТЛАЯ полоска ТОЛЬКО на правых стенах (у пола
  сторона 1 намотана как rect — дыры нет; левая стена/потолок не перекрываются). Зубцы покрывают кайму на всю
  глубину сами — `+1` был не нужен. Урок: воздушные прямоугольники и зубцы каймы в ОДНОМ пути клипа не должны
  перекрываться (встречная намотка subpath'ов в nonzero-клипе вычитается).
- `drawBoreMarks` — следы бура на стенках (кроме природной пещеры города). `drawResourceVeins` —
  жила кластером фигурок (`drawResourceCluster`), центр сдвинут от сетки.
- `drawCityMarkers`/`drawWildMarkers` — маркеры чужих городов/гнёзд (в дебаге — без тумана).
- `drawPlayerCity` — растровый ассет базы `assets/aztec_city/aztec_city.png` (`new Image()`,
  file:// ок): ширина = фундамент `(PRINTER.w+2)·TILE`, низ на полу `(CAVE_FLOOR_Y+1)·TILE`,
  центр = центр принтера. Плейсхолдер-прямоугольник принтера УБРАН (и в игре, и в интро).
- Рендер закольцован: диапазон X без клампа (lookups wrap), сущности — через `camera.screenX`.

## Свет и туман (render_light.js)

- `drawFog` — туман войны + мягкий градиент света (запас +1 тайл за вьюпортом). ⚠️ ФЕЙЛ-СЕЙФ: при
  вырожденном диапазоне тайлов заливает ПОЛНЫЙ туман (не пустой `return`) — иначе «весь экран чистый».
  Видимость — `world.isSeen` (туман войны) + дистанция до света. Радиус reveal — ЧЕСТНЫЕ ЦЕЛЫЕ тайлы
  (`world.reveal` = КРУГ Euclidean радиуса R, R = `round(scanR)`; дефолт 1 → апгрейд СЕНСОР 2 → 3).
  ⚠️ `reveal` САМА округляет r (`Math.round`): дробный r (напр. 3.5 при вскрытии базы из startSession) дал бы
  нецелые индексы Uint8Array → запись «в пустоту» → база не вскрывалась (интро на чёрном фоне). `FOG_EXPLORED`=0.6
  (исследованное вне света читаемо). `BG_FPS`=24 (окно не в фокусе — движение остаётся плавным).
  СГЛАЖИВАНИЕ: новооткрытый тайл проявляется не рывком — `world.revealT` (0..255, +`REVEAL_FADE_STEP`/кадр)
  миксует alpha от полного тумана к градиенту; при движении юнита фронт тумана отступает плавно.
  ⚠️ **СУБ-ТАЙЛОВОЕ разрешение фог-битмапа `SS`=3** (`cols*SS × rows*SS`, `lit`/дистанция считается суб-тайлово,
  `seen`/`revealT` — по родительскому тайлу). 1 пиксель/тайл + апскейл ×48 давал bilinear-ФАСЕТКИ плавного
  радиального градиента → видимые светлые/тёмные ПОЛОСЫ на границах тайлов (амплитуда ~6/255, заметна в темноте;
  `imageSmoothingQuality` не помогает — ошибка ∝ шагу²). Смещение `drawImage` ОКРУГЛЯЕТСЯ как в `drawWorld`
  (`Math.round(camera.x)`) — иначе фог сдвинут на ~0.5px от сетки тайлов.
- ⚠️ HUD-функции, меняющие `globalAlpha` (тусклые карточки/кнопки), ОБЯЗАНЫ `ctx.save()/restore()` —
  иначе утечка alpha в СЛЕД. кадр рисует мир/туман на 0.4 («туман пропал»). `drawPrintHud` обёрнут.
- `drawHeadlight` — прожектор-конус ОТ РЕАКТОРА (`unitLightAnchor`, дышит с idle) по взгляду.
  **⚠️ МИГАНИЕ:** притухает ТОЛЬКО конус (экран НЕ затемняем — убрано). Планировщик `_flickerDip` даёт
  ЯВНЫЕ провалы яркости со СЛУЧАЙНЫМ интервалом (0.7–4.5с) / глубиной / длительностью + дрожащий суб-паттерн
  внутри провала → нет ощущения «по кулдауну». `Math.random` ТОЛЬКО на СОБЫТИЕ (не per-frame → без стробо);
  сам провал — гладкая огибающая. Увод угла конуса — гладкими time-функциями. (Зависимости от projLvl нет.)
- `drawHeadlight` — прожектор-конус ОТ РЕАКТОРА (`unitLightAnchor`, дышит с idle) по взгляду.
  **Дефолт УЗКИЙ/КОРОТКИЙ/ТУСКЛЫЙ**, апгрейд **ПРОЖЕКТОР** (`mast_sens`, **3 уровня**, стат
  `unit.stats.projLvl` 0..3) растит ШИРИНУ+ЯРКОСТЬ+ДЛИНУ равномерно (без прожектора темно — норма):
  `half = 0.25 + projLvl·0.11` (ур.0 0.25 очень узкий → ур.3 0.58), `L = TILE·(3.5 + projLvl·0.9)`
  (3.5→6.2 тайла), яркость `cutA = 0.60 + projLvl·0.13` (тусклый→яркий) + glow `0.05 + projLvl·0.05`.
  `_coneVisibility` принимает `half` параметром.
  ОТСЕКАЕТСЯ ПОРОДОЙ ПО ВИЗУАЛЬНОЙ КРОМКЕ: `_coneVisibility` пускает веер лучей через `_coneSolid`
  (зона эрозии `_ragDepth` грани, выходящей в воздух, «открыта»; бисекция → стоп у рваной
  поверхности). BORDER/INDESTRUCT — прямой клип по сетке.
- Пенумбра: ядро резким клипом + резкий радиальный профиль; мягкость — только узкий размытый
  контур-«гало» (кэш-офскрин, destination-out). **Ambient-гало** ~1.3 тайла вокруг юнита без
  клипа — подсвечивает тайл в тупике, где конус схлопывается.
- **Пыль в луче**: отдельные пылинки-спрайты на параллакс-сетке (2 слоя), дрейф по Лиссажу
  (2 синусоиды/ось), анкер в мире через `camera.x·par`, фейд по дистанции, клип по конусу, аддитив.
  **Загрязнение**: `drawHeadlight` принимает `radLevel` (`game.radLevel` — уже считается КАЖДЫЙ кадр в
  playing-цикле, см. `spec_world.md`, новых опросов НЕТ). Доля зелёных пылинок = `radLevel` НАПРЯМУЮ по
  СТАБИЛЬНОМУ хешу `r4 < radLevel` → детерминированно (одна и та же крупинка устойчиво зелёная при данном
  radLevel; 0 → нет, 0.5 → половина, 1 → все). Зелёный — второй
  КЭШИРОВАННЫЙ спрайт-точка (`_dustDotRad`, кислотно-зелёный). Перф: лишь `drawImage` другого спрайта,
  без ветвления состояния.

## Сканер-лучи (render_scan.js)

- `_scanSrc` — апекс = модуль сканера (`ringModuleScreenPos(...,'sensor')`; фолбэк — центр юнита).
- `drawScanBeam(ctx,src,tx,ty,t,r)` — ОБЩИЙ киношный луч: полупрозрачный конус (раствор накрывает
  ±r цели), тусклые статичные стрики, ЯРКИЕ трассирующие лучи ходят от края до края, пятно контакта.
- Переиспользуют: `drawScanFx` (сервер-хлам + подсветка объекта), `drawEnemyScanFx`
  (`game.scanEnemy`), `drawBackdropScan` (объект пещеры-сцены, цель `b._astX/_astY/_astR`).
- `drawServers`: до откопки — тех-вкрапление с LED; после — кучка хлама (done → тусклее).
  В дебаге — все без тумана + метка `СЕРВЕР`/`DATA·NN`.

## Видения в темноте (visions.js / render_visions.js)

- Логика: редкие призрачные силуэты, **наплывают со стороны, ПРОТИВОПОЛОЖНОЙ взгляду**
  (`side = -unit.faceX` — там темно). Таймер `VISION_MIN_GAP..MAX_GAP`; простой юнита ускоряет
  (×`VISION_IDLE_RATE` после `VISION_IDLE_AFTER`). Огибающая `FADE_IN→LIFE→FADE_OUT`, пик
  `VISION_ALPHA` (очень низкий). **Взгляд повернулся к видению → мгновенное растворение**
  (`VISION_DISSIPATE`). `VISION_MAX`=1.
- Типы: `monster` (колоссальный шагоход на раскоряченных суставчатых ногах), `idol` (ступенчатый
  тотем), `landscape` (горизонт руин), `tendrils` (САМОСТОЯТЕЛЬНЫЕ 3 крупные ленты тянутся к юниту
  и пропадают недотянувшись), `glyphs` (лента ацтекских меандров бежит слева направо, паралакс).
- Рендер: нейтрально-холодный цвет, без светлых пятен/глаз; глитч — мерцающие срезы-сдвиги +
  тёмные глитч-квадраты (датамош) + сканлайны + радиальный edge-fade. Силуэт детерминирован сидом.
  Рисуется в экранных координатах ПОСЛЕ тумана/прожектора, ПОД юнитом; гейт `playing && !debug`.
  Перф: см. правила выше (прямой рендер, без filter/офскрина) — CPU ~0.01–0.03мс/кадр.

## Помехи интерфейса (render_glitch.js)

`drawInterference(ctx,canvas,intensity,t)` — пост-эффект ПОМЕХ от радиации (`game.radLevel`),
в пикселях канваса поверх ВСЕГО кадра (только playing, не дебаг). Снимок кадра + тонировка
каналов + тайл «снега». Стадии нарастают и НАКЛАДЫВАЮТСЯ: слабо — рой строк разной высоты
(~45% бьют по верхней зоне с HUD) + ранний RGB-сплит; средне — крупные срывы, бегущая полоса,
начало «снега»; сильно — снег густеет (перегенерация ~28Гц); критично — снег в НЕСКОЛЬКО проходов
со сдвигом (даже яркий UI тонет). Болезненный зелёный отлив на среднем+.
