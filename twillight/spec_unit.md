# spec_unit.md — Юнит: движение, бурение, риг, кольцо

> Реализованная спецификация. Код: `unit.js`, `unitdefs.js`, `anim.js`, `rig.js`,
> `render_unit.js`, `render_ring.js`, `render_parts.js`. Ноги-IK — `design_legs.md`.
> Конвейер «редактор → игра» — `design_editor.md`.

## Движение и бурение (unit.js) — ⚠️ ИНВАРИАНТЫ, НЕ ЛОМАТЬ

- **При пробитии тайла юнит НЕ двигается — РЕШЕНО С ИГРОКОМ.** Не добавлять `startMove`/движение
  в drill-блок на кадре пробития (ни для какого направления): юнит остаётся на месте, избыток
  мощности бура над остатком твёрдости отбрасывается.
- **«Замок» прокопанного тайла (`_dugBlock` + `DRILL_HOLD_ADVANCE`≈0.26с)**: въезд в ТОЛЬКО ЧТО
  пробитый тайл ТЕМ ЖЕ удержанием подавляется, пока направление не держат дольше порога.
  → Разовое нажатие (пробил → отпустил) = юнит СТОИТ. Удержание = непрерывный тоннель
  (бур держит стенки → бур ВНИЗ сквозь породу = плавный спуск, не падение). Замок снимается при
  отпускании направления. Обычная ходьба в открытый воздух (не свежепрокопанный тайл) — без замка.
  Авто-въезд в дыру на разовом нажатии — баг, был убран; следи, чтобы не вернулся.
- **Движение только с ОПОРЫ** (клинг к соседней породе): любой ход/лазанье/прыжок требует
  `anchored`, иначе гравитация; в свободном падении управление НЕ действует («полетать» вбок нельзя).
- Подъём по «вверх»: явный «вверх+вбок» → диагональ на уступ; «вверх» с опорой наверху → лезет по
  шахте/стене (без приседа); прямо вверх не зацепиться, но сбоку ЕДИНСТВЕННЫЙ уступ → авто-цепляние;
  только настоящий прыжок в ОТКРЫТЫЙ воздух даёт присед `crouchT` (`JUMP_CROUCH_T`) + замедленный
  прыжок (`JUMP_SPEED_FRAC`) — ощущение веса.
- `anchoredAt` — только соседняя порода (искусственных полов нет); пол стартовой пещеры держится
  за гарантированный породный грунт под ним.
- **Падение НЕПРЕРЫВНОЕ**: при завершении тайла в свободном падении тайлы цепляются в ОДНОМ кадре
  с переносом остатка `progress` — иначе `py` замирал на кадр → скачок скорости → ложный «удар»
  squash на каждом тайле (дёргано).
- **ХОД НЕПРЕРЫВНЫЙ** (так же): держишь горизонт. направление + впереди ОТКРЫТЫЙ тайл с опорой →
  следующий цепляется в ТОМ ЖЕ кадре (перенос остатка `progress`), без кадра-заморозки IDLE на стыке
  (иначе ~1 кадр стоп на КАЖДОМ тайле = «осечки по тайлам»). Не цепляем: свежепрокопанный (`_dugBlock`),
  ход в воздух без опоры (там гравитация). Разовое нажатие (отпустил) → не цепляет = один тайл.
- Порог пробития: тайл копит `tile.dig`; рассыпается при `digThreshold(t) = DIG_BASE(0.85с) ·
  hardness · tough(ресурса)` — ресурсный тайл крепче (`RESOURCE_DEFS[..].tough`: железо 1.4 /
  органика 1.5 / кристалл 1.9). Бур юнита делит порог через `digMult`.
- События: `unit.dug` — выкопан РЕСУРСНЫЙ тайл; `unit.broke` — прокопан ЛЮБОЙ тайл (game считает
  проходку `dugTiles` → рекорд `save.bestDug`).
- `hp/maxHp` из корпуса; `shove(nx,ny)` — мгновенный перенос со сбросом движения/бура (толчок
  валуном). `faceX` — последний ГОРИЗОНТАЛЬНЫЙ взгляд (риг/прожектор/видения).
- `stats.healRate` (HP за 10с от ремонт-трюма `cargo_repair`) — непрерывный реген HP в playing-цикле
  (`game`: `hp += healRate/10·dt`). 0 у обычного трюма. На базе добавляется РЕМОНТНЫЙ ДОК
  (`upgrades.cityDockRate`, узел ГОРОД). **ВФХ лечения СИНХРОНЕН РЕАЛЬНОМУ HP:** `game` хранит
  `_lastHpFloor` и спавнит зелёный «+» (`fx.heal`) РОВНО на пересечении целого HP (`floor(hp)` вырос) —
  одна частица = +1 HP, а не по таймеру/«пачкой» (`HEAL_FX_*` устарели). Всплывает и тает (`render_fx`).
- **Единый источник статов — `unit.stats`** (`setStats`): сборка (`inventory.getStats`) + апгрейды
  (`upgrades.applyToStats`) → движение/бур/сканер/HP/груз читают только его, отдельных кэшей нет.
  `effectiveSpeed()` = `stats.moveSpeed` (замедления от груза нет). Энергии/расхода нет.

## Импульсный бур (impulse.js, домешан в Game.prototype)

Вариант бура `MODULE_DEFS.drill_impulse` (слот `drill`, `impulse:1`, unlock `mast_di`). Альтернатива обычному:
**пассивно породу НЕ грызёт** — `getStats` ставит `s.impulse=true`+`s.altDrill=true` (+ `canDig` для рига), unit.js гасит
grind (`t.type===ROCK && s.canDig && !s.impulse`). Копание — ЗВУКОВОЙ ВОЛНОЙ в сторону взгляда.
- **Заряд** — удержание `Space` В ПОЛЕ (не на базе/печати), `imp.charge` 0→1 за `IMPULSE_CHARGE_T`(3.5с — ≈ время
  станд. бурения ~2 тайлов; «чуть эффективнее»). Пока копит — `unit.frozenImpulse=true` (юнит стоит). **АИМ = ВЗГЛЯД
  ЮНИТА** `[u.dx,u.dy]` (или `[faceX,0]`) — доп-клавиши при заряде НЕ нужны; повернул юнит заранее → бьёт туда.
  Заряд только из `state===IDLE`.
- **Выстрел** — на пороге максимума (авто) ИЛИ отпускании при `charge≥IMPULSE_MIN_FIRE`(0.05 — ДЕТЕРМИНИРОВАНО:
  любое отпускание бьёт пропорционально заряду, «мёртвой зоны» нет; гасится лишь 1-кадровый блип). `_impFire`
  создаёт ВОЛНУ (`imp.wave`), тайлы НЕ ломаются мгновенно.
- **Распространение** (`_impWaveAdvance`): фронт идёт от юнита наружу за `IMPULSE_WAVE_DUR`(0.7с — медленно, чтобы
  тайлы рушились по очереди ВИДИМО, не «поофф») на `len` тайлов
  (`IMPULSE_LEN`5 + `IMPULSE_LEN_NODE`3 при `mast_di_len`) — БЫСТРО, но ВИДИМО. На каждый достигнутый тайл сила с
  УГАСАНИЕМ: `force_i = peak·IMPULSE_FALLOFF^(i-1)`, `peak = charge·(IMPULSE_FORCE + stats.impForce)` (трек «СИЛА УДАРА»).
  Первый тайл — макс; `tile.dig += force_i`; хватило порога `digThreshold` → РАЗВАЛ (`setAir`, `dugTiles++`, `loot.spawn`,
  **`dust.burst`** — крошка, порода не исчезает а рассыпается); не хватило → `dig` остаётся = ТРЕЩИНЫ (render_world рисует
  по `dig/threshold`). Дальний тайл «трескается», не ломается. Враги: `IMPULSE_DMG·force_i/IMPULSE_FORCE` (ближе сильнее).
  BORDER/INDESTRUCT — стоп. По умолчанию (H≈2) полный заряд ломает ~3-4 тайла + 1 в трещинах.
  **`wave.reach`** (в `_impFire`) = до какого тайла сила ещё ≥ `IMPULSE_MIN_EFFECT`(1.0) — РЕАЛЬНАЯ дальность эффекта
  (масштаб от заряда/`impForce`/узла длины); по ней рисуется визуал (не «в пустоту» за концом).
- Рендер — `render_impulse.js` `drawImpulseWave` (УЗКО-НАПРАВЛЕННОЕ ИСКАЖЕНИЕ ВОЗДУХА: тонкая ПОЛОСА вдоль взгляда —
  слабый хейз + ДРОЖАЩИЕ поперечные гребни, сильнее у юнита, тают к концу; ПРИГЛУШЕНО — не светит; длина = `wave.reach`,
  не `len`. БЕЗ яркой линии фронта, не конус) + `drawImpulseCharge` (дуга заряда + стрелка-взгляд).
  ⚠️ без `ctx.filter` (градиент/пути — ок). `game.imp` (сброс в `startSession`).

## Кинетический бур (unit.js, ramp в drill-блоке)

Вариант бура `MODULE_DEFS.drill_kinetic` (`kinetic:1`, `digMult:KIN_BASE_MULT`=0.6, unlock `mast_dk`). В отличие от
импульсного — **обычный grind** (упор в породу), но РАЗГОНЯЕТСЯ при НЕПРЕРЫВНОМ бурении. Логика — В `unit.js`
(это модификация grind-ветки), не отдельный файл.
- **Разгон ПО ВРЕМЕНИ** (не по тайлам): `kinRamp` 0→1 копится `+dt/KIN_RAMP_TIME`(5с) на КАЖДОМ кадре бурения породы
  — даже на ОДНОМ твёрдом тайле растёт, пока долбишь (не ждём пробития). Мощность = `s.digMult + (KIN_MAX_MULT −
  s.digMult)·kinRamp + (s.kinPower||0)`; старт `KIN_BASE_MULT`=0.5 (вдвое медленнее стандарта ×1.0) → полный `KIN_MAX_MULT`=2.5.
- **Сброс разгона** (`kinRamp=0`, `kinDir=null`): (1) отпустил направление; (2) перестал бить породу дольше `KIN_GRACE`=0.8с
  (стоп/пустота — `kinIdleT`, drill-блок его обнуляет → пауза между тайлами разгон ДЕРЖИТ); (3) **СМЕНА НАПРАВЛЕНИЯ**
  бурения (`kinDir` = `dx,dy`; в drill-блоке отличается → сброс) — копаем ПО ПРЯМОЙ разгон растёт, повернул — обнуление.
  `shove` (валун) тоже сбрасывает.
- **Город:** трек «КИНЕТИКА» (`kinpower`→`kinPower`, при `s.kinetic`) сдвигает кривую вверх; «СИЛА БУРА» скрыта при
  ЛЮБОМ спец-буре (`s.altDrill`). Узел меты **`mast_dk_max`** «Тяжёлый боёк» → потолок разгона `s.kinMax` 2.5→**3.0**
  (`KIN_MAX_MULT_NODE`, ставится в `getStats`) И третий уровень трека «КИНЕТИКА» (`metaCap:{node:'mast_dk_max',cap:3}`).
- **ВЗРЫВНОЙ ПРОБОЙ — узел `mast_dk_burst`** (вторая ветка от `mast_dk`, вверх; отдельно от тяжёлого бойка): при пробитии
  тайла кинетикой, если `kinRamp ≥ KIN_BURST_MIN_RAMP` и `metaHas('mast_dk_burst')`, с шансом `KIN_BURST_CHANCE`(0.10) +
  трек ГОРОДА «РАЗГОН ПРОБОЯ» (`kinburst`→`s.kinBurstBonus`, gate узлом, +`KIN_BURST_STEP`/ур, cap 2 → макс 0.30) ПРАЙМИТСЯ
  суперзаряд (`unit.kinCharged=true`). ⚠️ НЕ пробивает второй тайл сразу (это рвало бы разгон) — вместо этого **СЛЕДУЮЩАЯ
  тычка по породе мгновенна**: в drill-блоке `kinCharged` даёт `t.dig += digThreshold(t)` → тайл дробится за один контакт
  (`superHit`). Копка непрерывна (тот же `kinDir`) → РАЗГОН СОХРАНЯЕТСЯ. Заряд гаснет со сбросом разгона (стоп/поворот/grace).
  Лут/проходка — обычным путём (`dug`/`broke`); FX на пробитом тайле — `unit.kinBurstFx` → `game` (`dust.burst` + `fx.hit`).
- Рендер — `render_impulse.js` `drawKineticHeat` (ТОЛЬКО полоска разгона над юнитом по `kinRamp`; точки на тайле НЕТ).
  Поля `unit.kinRamp`/`kinDir`/`kinIdleT`.

## Винтовой бур-проходка (borers.js, домешан в Game.prototype)

Вариант бура `MODULE_DEFS.drill_screw` (`screw:1`, unlock `mast_ds`). Юнит = СТАНЦИЯ автономных буров: сам не
грызёт (`s.screw`+`s.altDrill`, unit.js гасит grind), а по Пробелу запускает АВТОНОМНЫЕ щиты.
- **Запуск/возврат — Пробел** В ПОЛЕ (`updateBorers`, `input.pressed`): если в радиусе `SCREW_RECALL_R`(1.4т) есть щит —
  «забрать» ближайший (счётчик восстановлен); иначе, если развёрнуто < `borerMax`, запустить новый СТРОГО по взгляду `[u.dx,u.dy]`.
- **Щит** (`game.borers[]`, поля `tileX/tileY/px/py/dx/dy/spin`): `_borerStep` каждый кадр — бурит тайл ВПЕРЁД
  (`tile.dig += SCREW_DIG_BASE + stats.screwSpeed`); пробил → `setAir(...,noTrigger=true)` (УКРЕПЛЁННЫЙ ход — НЕ
  осыпает породу/валуны), `tile.screw=true` (метка текстуры), `tile.screwAxis` = 0/1 (ось хода гориз/верт → разворот
  текстуры), `dugTiles++`, `loot.spawn`, `dust.burst` (крошка), `b.drilling=true` (анимация работы), и продвигается
  на освободившийся тайл. **Медленно/слабо по умолчанию (`SCREW_DIG_BASE`=0.275/с)** — «set & follow».
- **ХОД / АНКЕР / ГРАВИТАЦИЯ** (`_borerStep`, ПРИОРИТЕТ сверху вниз): **(1) впереди ПОРОДА → бурит её в ЛЮБУЮ
  сторону** (в т.ч. ВВЕРХ — «держится» за породу; гравитация не проверяется → нет дёрганья «вверх↔вниз» и можно
  прокапываться вверх). **(2) породы по ходу нет и СНИЗУ пусто → ПАДАЕТ** `SCREW_FALL_SPEED`(9 т/с) (пещера/обрыв).
  **(3) опора есть, впереди открыто → ход по воздуху** `SCREW_AIR_SPEED`(4 т/с), но НЕ ВВЕРХ (вверх без породы не
  лезет — просто ЛЕЖИТ, не взлетает). Иначе (край/индестракт/ход вверх в пустоту при опоре) — стоит. `b.moveT` — таймер шага.
- **Ёмкость:** `stats.borerMax` = `SCREW_BORERS_BASE`(2) + узлы меты `mast_ds_b1`/`mast_ds_b2` (+1 каждый → макс 4).
- **АПКИП (автономный заряд):** каждый щит несёт ЗАРЯД работы `b.charge`/`b.maxCharge` (= `borerLife()` = `SCREW_CHARGE_MAX`(16с)
  + трек `stats.borerLife`). `_borerStep` тратит `dt` пока щит АКТИВЕН; `charge≤0` → `b.depleted=true` (щит ЛЕЖИТ — глайд к
  центру тайла, но НЕ копает/не движется, спин стоп; лог `borerDepleted`). **ПОДЗАРЯДКА** (`_borerRecharge`, зовётся из
  `updateBorers` для `depleted`): юнит в `SCREW_RECHARGE_R`(1.6т, чуть >recall) → `charge` копится со скоростью
  `maxCharge/SCREW_RECHARGE_TIME`(1.2с) → полный → `depleted=false`, продолжает ход (если игрок не «забрал» Пробелом;
  `b.recharging` — флаг пульс-анимации). Юнит отошёл — пауза (заряд НЕ сбрасывается). НЕ завязано на энергию юнита — это
  автономность щита. Поле заряда лениво создаётся (`b.charge==null` → `borerLife()`).
- **Город:** трек «СКОРОСТЬ ПРОХОДКИ» (`screwspeed`→`screwSpeed`, при `s.screw`, 3 ур.).
- **Апгрейд апкипа — УЗЕЛ МЕТЫ** (не трек): `mast_ds_life` «Ресурс автономии» — ПЕРВЫЙ узел ветки бура
  (`mast_ds → ds_life → ds_b1 → ds_b2`: автономия раньше ёмкости); `metaHas('mast_ds_life')` → `borerLife()` +=
  `SCREW_LIFE_BONUS` (заряд 16→32с). Три слота ветки позиционно неизменны — узлы лишь переставлены по порядку.
- **Магазин на юните:** несомые (`borerMax − borers.length`) щиты — «следующий» торчит из порта юнита и
  ПОВОРАЧИВАЕТСЯ ВМЕСТЕ С ЮНИТОМ (как простой бур — по `unit._ringAim`/`faceX`), не всегда горизонтально
  (`drawCarriedBorer`, рисуется ДО юнита → задняя половина под кольцом; пусто, когда несомых 0). При деплое щит
  выезжает из юнита (glide от центра) и идёт сам. HUD-статус — `hud.drawBorerStatus` (низ-лево): слот на каждый
  щит, НЕСОМ (залит) / В ХОДУ (контур) + «НЕСУ N · В ХОДУ M». Гейт — `unit.stats.screw`.
- **Узлы 2-й ветки (`mast_ds`):** `mast_ds_nav` — `drawBorerArrows` (стрелки вокруг юнита на щиты, гейт
  `metaHas('mast_ds_nav')`); `mast_ds_scan` — каждый щит зовёт `world.reveal(b.tileX,b.tileY, scanR)` в `updateBorers`
  (снимает туман, гейт `metaHas('mast_ds_scan')`).
- Рендер — `render_borer.js`: `drawBorers` (проходческий щит — УЗКИЙ вдоль хода, ВЫСОКИЙ поперёк ≈ калибр, +
  фреза-диск спереди; `b.drilling` → анимация работы: фреза быстрее + искры; **ПОВЕРХ тумана**) · `drawCarriedBorer`
  (несомый, поворот с юнитом) · `drawBorerArrows` (узел nav: стрелки + неяркая цифра ДИСТАНЦИИ в тайлах, round →
  без джиттера) · `drawScrewTrail` (тихий след, рёбра ⊥ `t.screwAxis`, ПОД туманом). `_shieldBody(alongH,perpH,
  spin,drilling)` — общий корпус. Состояние `game.borers` (сброс `[]` в `startSession`).
- **ДЕТАЛЬ-БУР СКРЫТА при винтовом.** Вид винтового бура = ЩИТ (не деталь-бур в слоте). `drawRingUnit`/`drawTachikoma`
  ПРОПУСКАЮТ `p.kind==='drill'` при `unit.stats.screw` (иначе дублировался бы дженерик-бур поверх щита). В ИГРЕ щит на
  юните даёт `drawCarriedBorer` (с учётом деплоя: `carried=max−deployed`, при 0 не рисует). На СТАТИЧНОМ превью (экран
  сборки `drawInventory`, где `drawCarriedBorer` не зовётся) — `drawMountedBorer(ctx,cx,cy,aim)` (render_borer.js);
  `_dummyUnit` для этого ставит `stats.screw` из `MODULE_DEFS[drill].screw`. В редакторе рига — свой `drawBorerOnUnit`.
  ⚠️ **ЕДИНЫЙ калибр/вынос `BORER_ON_UNIT`** (render_borer.js: `{alongH:TILE·0.14, perpH:TILE·0.27, off:TILE·0.5}`) —
  ОДИН источник для игры/сборки/редактор-превью. Иначе `k=perpH/(TILE·0.3)` разный → авторские `offX/offY` ассета
  «не передаются» (читаются в разном масштабе). ⚠️ **Автономный ДЕПЛОЙ-щит (`drawBorers`)** тоже масштабируется на `unitDrawScale`
  (запущен юнитом → его калибр, иначе крупнее юнита) И рисуется с `shieldOnly=true` — ТОЛЬКО `borer:shield` (бур-щит), БЕЗ
  `borer:mount`: крепление — ПОРТ, остаётся на юните (в несомом/сборке есть, в деплое «не едет» с проходческим щитом). Флаг
  `shieldOnly` протянут `_shieldBody`→`_borerAsset` (пропускает `blit(mount)`). Индикаторы заряда/подзарядки в `drawBorers` —
  в том же масштабе `s`, но штрих/шрифт делятся на `s` (остаются читаемыми у мелкого щита).
  ⚠️ **`drawCarriedBorer` МАСШТАБИРУЕТ щит на `unitDrawScale(u)`** (=`def.drawScale`, у core 0.4428) — кольцо рисуется в
  этом масштабе, щит ДОЛЖЕН ужиматься вместе (иначе в игре был ×2.25 крупнее/дальше, чем в редакторе, где full R).
  Плюс принимает `bodyOff` (лаг корпуса на щупальцах, тот же `tOff`, что кольцо) → щит НЕ отстаёт от корпуса при bob/ходе.
  Итог: редактор == сборка == игра (замер: смещение/радиус кольца = 1.143 во всех трёх, dy=0).
- **ГАЛЕРЕЯ СБОРКИ:** карточка `drill_screw` (`render_inventory._invDrawCard`, спец-кейс перед откатом на `mod:`/деталь)
  рисует СОСТАВНОЙ ЩИТ через **`drawBorerFit(ctx, boxW, boxH)`** (render_borer.js) — он МЕРЯЕТ реальный bbox спрайтов
  mount+shield и ВПИСЫВАЕТ+ЦЕНТРИРУЕТ в бокс карточки. ⚠️ НЕ `_shieldBody` напрямую: там размер = `img·scale·k` (калибр-
  зависимый `k`), на крупной иконке ассет РАЗДУВАЛО за карточку. `drawBorerFit` не зависит от калибра → не вылезает/не смещён.
- **СОСТАВНОЙ АССЕТ** (опционально; фолбэк — процедурный корпус выше): `_shieldBody` рисует СПРАЙТЫ, если в
  `PART_SPRITES` лежат `borer:mount` (КРЕПЛЕНИЕ, задний слой) и/или `borer:shield` (БУР-ЩИТ, передний). Обе части в
  каноническом кадре (вперёд=+X), рисуются под ротацией щита по направлению проходки; масштаб `k`=калибр/`TILE·0.3`
  (автономный TILE·0.3 → k=1, несомый TILE·0.27 → k≈0.9). Искры-крошка (`_borerSparks`) поверх при `drilling` в
  ОБОИХ режимах. Ассеты — ГЛОБАЛЬНЫЕ ключи в `module_assets.js` (генерит редакторская секция «Бур-щит (составной)»,
  `design_editor.md` §16), грузятся `new Image()`→`setPartSprite` ДО game.

## РАДАР / ЭХО сканеры (scanners.js, домешан в Game.prototype; рендер render_scanners.js)

Два **варианта слота СКАНЕР** (взаимоисключающие со стандартным `scanner`, как альт-буры): открываются узлами
СЕТИ ПАМЯТИ, ставятся в слот сканера. Оба с **фиксированным `scanR:1`** — туман снимается честным 1 тайлом
(`spec_render`); сканеры НЕ раскрывают породу, только ищут залежи. `getStats` ставит `s.radar`/`s.echoScan`
(+ `s.radarSpectrum`/`s.echoLong` из узлов-детей). Состояние — `_scanInit()` в `startSession`; тик — `updateScanners`.
**Активация ОБОИХ — ЦИФРА 1** (`moduleActionKeys('scanner',…)` → `_scanWantFire`): сканер — ДОПОЛНИТЕЛЬНОЕ действие (своя цифра), бур — ГЛАВНОЕ
(Пробел), поэтому НЕ конфликтуют ни при какой сборке (общее правило — `constants.js` `KEY_PRIMARY`/`KEY_ACTION(n)`/
`MODULE_ACTION` (`scanner:1`); см. CLAUDE.md `input.js`). Оба РАБОТАЮТ НА КУЛДАУНЕ. Стандартный трек СЕНСОР (радиус) скрыт при
радаре/эхо (`need: scanR>0 && !radar && !echoScan`) — у них вместо радиуса трек кулдауна.

- **РАДАР** (`scanner_radar`, unlock `mast_rad`, `s.radar`): по активации (cd≤0) делает **ОДИН оборот** развёртки
  (`radarSweep.sweeping`, период `RADAR_SWEEP_PERIOD`≈6.8с — НЕ непрерывно), радиус `RADAR_R`. Залежь/враг, чей
  пеленг попал в свежепройденный клин, → БЛИП (`_radarBlip`); держатся ~до следующей развёртки (`fade=period+cd`).
  По завершении оборота — кулдаун `RADAR_CD_BASE`. Залежи кэшируются (`_radarCollect`); враги — каждый кадр.
  **Фильтр типа** (`radarSweep.resType`) — клавиша **C**/клик по чипу (`radarCycleType`); узел `mast_rad_spec`
  (`s.radarSpectrum`) снимает фильтр → все типы, чип скрыт. Враг-блип — красный с крестиком.
- **ЭХО** (`scanner_echo`, unlock `mast_ech`, `s.echoScan`): по активации (cd≤0) волна `echo.wave` за `ECHO_WAVE_T`
  до `ECHO_R` (×2 при `mast_ech_len`/`s.echoLong`) метит ВСЕ залежи (`_echoMark`, держатся `ECHO_MARK_FADE`).
  Кулдаун `ECHO_CD_BASE`.
- **Кулдаун-треки** (`cat:'unit'`, при `s.radar`/`s.echoScan`): `radarcd` («ОХЛАЖДЕНИЕ РАДАРА», `radarCdD`) и
  `echocd` («ВСПЫШКА ЭХО», `echoCdD`) — NEGATIVE step → кулдаун ↓ до `RADAR_CD_MIN`/`ECHO_CD_MIN`. Потребитель:
  `CD_BASE + (stats.delta||0)`, клампится (снимок в `cdMax` при срабатывании).
- **Рендер** (`render_scanners.js`, ПОВЕРХ тумана): `drawRadarSweep` (веер+кольца ТОЛЬКО во время оборота + блипы
  с затуханием), `drawEchoWave` (лиловые кольца-искажение + метки), `drawRadarSwitch` (чип типа, лево), **`drawScanCooldown`**
  (виджет кулдауна — ПРАВЫЙ ВЕРХ под тумблером ПУТЬ `navHudRect`, y32 — НЕ пересекается; СКАН…/перезарядка/ГОТОВ+клавиша).
  ⚠️ ПРИГЛУШЁННО, перф: `'lighter'`, без `ctx.filter`/`shadowBlur`/офскринов.

  `supportDirOf(world,unit)` — пол снизу → `down`, иначе боковая стенка. `legHub` — пивот приседа.

## Юнит-КОЛЬЦО (render_ring.js — корпус core, дефолтный)

- Центр — ТОР-реактор (деталь `kind:'reactor'`, УЧАСТВУЕТ в общем z-порядке); модули снаружи по
  окружности (в блупринте `ang°`+`rad` в R), ориентированы наружу.
- Ориентация кластера: `updateRingAim(dt,unit)` → `unit._ringAim` (ПЛАВНО, только вертикаль ±90°)
  + `unit._ringFlip` (МГНОВЕННОЕ зеркало). **Строго налево = ЗЕРКАЛО вида (`scale(-1,1)`), НЕ
  поворот на 180°** (иначе верхние модули уходят вниз под ноги). Вертикаль из `unit.dy` (не из
  `drilling`) → направление СОХРАНЯЕТСЯ после бурения вверх/вниз.
- Бур «долбит»: при `drilling` радиус крепления бура модулируется `ANIM.drillWob`.
- **Масштаб — ОДИН `ctx.scale(opts.scale)` на всё кольцо** (позиции И спрайты ужимаются вместе;
  иначе спрайты выходили в 1/scale крупнее, чем в редакторе). `R=(TILE-8)/2` в дизайн-px.
- Реактор ВЫКЛ (`reactorOn===false`, интро до установки): ассет `reactor:off`, иначе вкл-спрайт
  с альфой 0.4 / процедурный тор с потухшим ядром.
- НОГИ не вращаются — это щупальца (`tentacles`/`legik`), рисуются ОТДЕЛЬНО в `game.drawScene`
  ПОД кольцом: клип-видимый-воздух → `drawTentacles` → `drawRingUnit`.
- `ringModuleScreenPos(unit,camera,kind,bo)` — экранная позиция модуля кольца (та же раскладка
  translate→scale→flip→cos/sin(ang+aim)·rad·R); используется лучами сканера. Апекс сканера ищет
  `kind:'sensor'` (НЕ 'scanner' — то флаг-стат `need`).
- Прожектор кольца: `unitLightAnchor` — отдельная ветка (вершина у бура, направление = угол бура
  `drill.ang+_ringAim` с учётом `_ringFlip`).

## Корпус «СПРУТ» — якорные щупальца (sprut.js / render_sprut.js)

Hull `sprut` = `kind:'ring'` + флаг `def.anchorLegs` (тело/модули/доворот кластера — как core), unlock —
узел `print_slots` (РЕАЛИЗОВАН полностью, wip снят). HP как core (`SPRUT_HULL_HP`). Все числа `SPRUT_*` —
СТАРТОВЫЕ значения, тюнить в браузере.

**ДВА ДОП-СЛОТА (главное свойство корпуса):** slots = […, 'aux', 'aux2'], оба optional. Слот `aux2`
принимает модули КАТЕГОРИИ 'aux' — маппинг `inventory._slotCat(slot)` (слот ≠ категория; применён в
defaultBuild/loadBuild/_categoryActive/computeCards). `_categoryActive` первым делом гейтит «слот есть у
корпуса» (aux2 виден только у спрута). Карточка галереи несёт КЛЮЧ СЛОТА в `card.category` — клик ставит
в слот своей секции; ОДИН И ТОТ ЖЕ модуль в двух слотах не дублится (pointerDown: переезд из парного слота).
getStats ставит `s.auxOn`/`s.aux2On` (занятость) → unitHasPart need 'aux'/'aux2' (rig.js) → деталь `aux2`
(kind 'aux', ang −118°) видна при занятом втором слоте; спрайт варианта — PART2CAT.aux2 (render_parts).
SLOT_META.aux2 ищет деталь по `partId` (kind 'aux' дублируется). Секция галереи — «ДОП-СЛОТ II».

**ЯКОРНЫЙ МОСТ (unit.js `anchoredAt`, только anchorLegs):** доп-опора «щупальца держат за обе стороны»:
юнит заякорен в воздушном тайле, если С ОБЕИХ сторон в пределах 3 тайлов есть НИЖНЯЯ КРОМКА (solid на
`(±k, y+1)` с ВОЗДУХОМ над ним — верх пола, НЕ отвесная стена; отвесные стены исключены сознательно,
иначе «распорка»-вис в шахтах = отвергнутый вис). Дыры в полу шириной ≤3 проходятся ЦЕЛИКОМ (ход/стойка/
прыжок над дырой работают через общий isAnchored); ≥5 — честное падение. ⚠️ `nav.js` мост НЕ знает
(A*-путь домой консервативен) — приемлемо. Риг сам тянет ноги к кромкам (cast честный).

**РАПЕЛЬ (unit.js, только anchorLegs):** шаг ВНИЗ (S) с опоры в БЕЗОПОРНЫЙ воздух (обрыв/потолок полости)
взводит трос `unit.rappel={hx,hy}` (точка схода). `_rappelHold(world)` держит, пока юнит В ТОЙ ЖЕ колонне,
глубина ≤ `SPRUT_RAPPEL_LEN` (3) и у точки схода есть порода (`anchoredAt(hx,hy)`, вкл. мост) — иначе
трос рвётся (сам чистит `rappel`) → обычное падение. Держит = ГЕЙТЫ в двух местах гравитации: falling-чейн
MOVING (строка ~192) и IDLE-гравитация — оба `&& !_rappelHold`. Управление висом (ветка ПЕРЕД wantUp):
S — стравить ниже (скорость юнита, до предела), W — подтянуться (на подвесе anchored → трос сматывается,
`rappel=null` в IDLE-ветке anchored), A/D — сойти на соседнюю опору (кромку/мост), без ввода — ВИСИТ.
Риг: вис = «заякорен» для слоя ног (updateSprutLegs: `anch = isAnchored || _rappelHold`) — верхние ноги
сами цепляются за кромку подвеса, шлейф-режим не включается.

**Ноги — 8 ПРЯМЫХ щупалец-якорей** (НЕ legik/IK): детали `kind:'anchor'` в блупринте, `ang`/`rad` =
расстановка КРЕПЛЕНИЙ по кругу (4 нижних 30..150° + 4 верхних −30..−150°; правится в редакторе
перетаскиванием ручек — редактор кольца даёт это бесплатно, aim к якорям НЕ применяется). Число ног
расширяемо: система читает ВСЕ `kind:'anchor'` детали.

- **Стейт-машина ноги:** `folded` (культя `SPRUT_FOLD_LEN`) → `fire` (выстрел к цели, `SPRUT_FIRE_T`,
  easeOut) → `hold` (хват; якорь ФИКСИРОВАН в мире — щупальце поворачивается вокруг крепления при
  движении корпуса) → `retract` (`SPRUT_RETRACT_T`, втягивание от точки отпускания `L.rx/ry`) → folded.
- **Выбор цели:** луч-марш по тайлам от крепления наружу (шаг TILE/3, дальность `SPRUT_REACH` тайлов),
  веер углов вокруг нормали крепления (0, ±0.3, ±0.6 рад) — первый ТВЁРДЫЙ тайл = точка хвата.
- **Перецеп (hold → retract):** порода выкопана / растяжка >`SPRUT_OVERSTRETCH`×reach (жёсткий срыв
  ×1.35 — мимо очереди) / при движении якорь «позади» на >`SPRUT_BEHIND_FRAC`×reach.
- **ВОЛНА:** глобальный гейт `rig.fireGate=SPRUT_STAGGER` — выстрелы/мягкие перецепы по ОЧЕРЕДИ
  (октопус-ритм, не разом); личный кулдаун ноги `SPRUT_REFIRE_CD`.
- **ГРЕБОК (анимация хода):** при устойчивом движении перецепы идут РИТМИЧНОЙ волной по кругу
  (`rig.gaitT`/`gaitI`, период `SPRUT_GAIT_PERIOD`) — не ждём перерастяжки; нога, чей якорь уже вынесен
  вперёд (>0.35·reach по ходу), пропускается. Веер выстрела НАКЛОНЯЕТСЯ к ходу: базовый угол = микс
  вектора нормали крепления и вектора скорости (`SPRUT_GAIT_BIAS`) — ноги тянутся ВПЕРЁД.
- **ПРЫЖОК-«СТРАЖ» («Матрица»):** присед юнита (`unit.crouchT`, счёт вниз) → корпус ВЖИМАЕТСЯ на якорях
  (`squat` в bodyOff, глубже к отрыву, `SPRUT_SQUAT`; лерп ускорен ×18 — присед всего 0.09с) → на истечении
  приседа КАТАПУЛЬТА: `rig.kick` вверх+по ходу (`SPRUT_KICK`, спад exp(−6t)) + взводится `rig.jumpT`=0.6.
  ⚠️ **`airLike`** = `!anchored || (jumpT>0 && mvy<−10)`: тайловая модель держит `isAnchored=true` ВЕСЬ
  подъём — без airLike ноги суетились бы перецепами вместо шлейфа. При airLike ВСЕ хваты рвутся, выстрелы
  заблокированы, ноги — ШЛЕЙФОМ ЗА корпусом (веер ПРОТИВ скорости `rig.tdx/tdy`, длина `SPRUT_TRAIL_LEN`,
  разброс `SPRUT_TRAIL_SPREAD`, трепетание). Приземление: вжатие-kick ПО вектору удара (отпружинивает
  спадом) + ЗАЛП перецепов волной (кулдауны i·0.04). Гейты гребка/щупа/визуала — тоже `airLike`.
- **ПОИСКОВЫЕ ДВИЖЕНИЯ (idle):** сложенные ноги медленно покачиваются вокруг нормали (`SPRUT_SWAY_AMP`,
  амплитуда гаснет при движении) и «дышат» длиной; стоя на месте свободная нога (folded И (неактивна ИЛИ
  без кандидата опоры)) изредка делает холостой ЩУП в пустоту — state `'probe'`: вылет `SPRUT_PROBE_LEN`·reach
  (0.25с) → зависание с РАСКРЫТОЙ лапой (`L.vopen`, 0.3с) → возврат; один за раз, пауза `SPRUT_PROBE_CD`.
  Визуальная поза сложенных ног — `L.vdir`/`L.vlen` (лерп к цели в степпере) — рендер читает ИХ, не константы.
- **СОСКАЛЬЗЫВАНИЕ:** якорь в НЕСТАБИЛЬНОЙ породе (`env.unstableAt` ← `t.unstable`) «скребёт» — дрожь лапы
  `L.slipJ` (рендер добавляет перпендикулярный джиттер) — и через `SPRUT_SLIP_TIME` СРЫВАЕТСЯ: отцеп +
  вздрагивание корпуса (kick ОТ точки срыва) + быстрый перецеп (cd 0.12). Перецеп в тот же нестабильный
  тайл даёт повторный скрежет — читается как «карабкается по осыпи».
- **ОТКРЫТОЕ ПРОСТРАНСТВО (правило 8→4):** с ≥3 из 4 сторон подряд ≥2 тайла ВОЗДУХА (`openCount`) →
  активны только `SPRUT_LEGS_OPEN`=4 ноги с ближайшими кандидатами опоры (ранжирование раз в 0.25с),
  прочие складываются; гистерезис `SPRUT_OPEN_HYST` (анти-мерцание у кромок).
- **Воздух/прыжок:** юнит не `isAnchored` → все хваты отпускаются (поджим «торпедой»); приземление →
  залп перецепов с фазовым сдвигом (кулдауны i·0.05).
- **Подвес корпуса:** `sprutBodyOffset()` — тяга к натянутым якорям + «дыхание», кап `SPRUT_BODY_SWAY`;
  в `game.drawScene` идёт как `tOff` (вместо `tentacleBodyOffset`), хипы ног едут вместе с телом.
- **Физику юнита НЕ трогает** (чистый визуал, как tentacles): опора/клинг/падение решает unit.js.
- **env-инъекция** (один степпер `sprutRigStep` на игру и превью): игра — тайл-марш по world (тор
  через `wrapDeltaPx`/`normX`); превью — аналитическая «камера» из плоскостей (`envFromChamber`):
  редактор цепляется к линейке пол/потолок (+фикс. стены ±2.2 тайла), сборка — к фейк-камере
  (floor TILE·1.15 / ceil −1.5 / стены ±1.9; `_invDrawBlueprint` ветка `anchorDef`, посадка `b.cy`
  по полу камеры; габарит — `blueprintScale` добавляет `TILE·2.05`). Редактор двигает крепления
  живьём — `sprutPreviewStep` синхронит ang/rad in-place без сброса состояний.
- **Рендер:** звенья `sprut:link` ТИРАЖОМ вдоль луча (шаг `SPRUT_LINK_SPACING`) + лапа `sprut:claw`
  на конце (раскрывается при хвате) — ГЛОБАЛЬНЫЕ плоские ключи (как `wheel:*`; исключения —
  rigbridge.js + buildIngameFile + exportModuleAssets редактора, секция «Спрут: щупальце-якорь»).
  Нет ассетов → процедурный фолбэк (тёмный луч + бронзовое ребро + точки-сочленения + трёхпалая
  лапа + гнездо). Ноги ПОД кольцом в клипе видимого воздуха; вспышка-сердцевина на выстреле.
  `drawRingUnit` детали `kind:'anchor'` пропускает (не деталь кластера, не вращается с aim).

## Спрайты деталей (render_parts.js)

Деталь рисуется в каноническом кадре (центр 0,0, вперёд +X); `drawPart` подменяет процедуру на
спрайт из `PART_SPRITES[opts.id]` (ассет НА ДЕТАЛЬ). `setPartSprite(id,img,scale,offX,offY,rot)`;
`PART_SPRITE_SRC` — авто-загрузка через `new Image()` (работает на file://). `drawLeg` — сегментная
нога (спрайт с пивотом px/py ИЛИ капсула); `drawCable` — кибер-мускул/ассет-кабель.
**Спрайты привязаны к ТИПУ КОРПУСА** (namespacing `<hull>:<id>`, `partsHull(unit.hull)` +
`spriteFor` с откатом на плоский id) — `core` и `scout` не делят ассеты. Приём из редактора:
`rigbridge.js` (localStorage, один origin) / `rig-core.js` (файл, работает на file://) —
детали в `design_editor.md` §11.
- **Спрайт КОНКРЕТНОГО варианта модуля** (`partSpriteId(unit, partId)`): деталь корпуса (kind) →
  слот-категория (`PART2CAT`) → установленный модуль (`unit.modules`) → если есть `spriteFor('mod:<id>')`,
  деталь рисуется ЭТИМ спрайтом, иначе обычным спрайтом детали. Так варианты слота (cargo/cargo_repair…)
  выглядят по-разному на корпусе И в галерее. Манифест `module_assets.js` (генерит редактор) — см.
  `design_editor.md` §15. `unit.modules` ставит `game.startSession`, превью сборки — `inventory._dummyUnit`.
