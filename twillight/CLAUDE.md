## 1. Проект

**Twilight of the World (Сумерки мира)** — roguelite-копалка, вид сбоку, с
гравитацией. Игрок-ИИ через
базу-принтер управляет ботами-бурами: бот выходит на поверхность, копает вглубь,
добывает ресурс, возвращается. Дизайн-источник — `gdd_mvp_v0.3.md` (этап M0+).

**Стек:** чистый HTML + JS + Canvas 2D. **Без npm, без сборщиков, без фреймворков.**
Открывается двойным кликом по `index.html`. Главный цикл — `requestAnimationFrame`.

**Что уже есть:** тайловый мир со слоями/твёрдостью, юнит-Tachikoma (ход/лазанье/
гравитация/клинг к породе/авто-копание), энергия выводится из модульной сборки
(«ядро»), гекс-конструктор модулей, меню/пауза, сохранение лучших метрик в
localStorage.

## 2. Запуск и проверка

- **Запуск:** `index.html` двойным кликом, либо статик-сервер из
  `.claude/launch.json` (порт 8123).
- **После КАЖДОГО изменения проверяй в браузере** (preview): скриншот ключевых
  экранов + `preview_console_logs` (ошибок быть не должно).
- **rAF в превью тормозит** между «тихими» eval-вызовами (фоновая вкладка). Чтобы
  проверить логику детерминированно — шагай симуляцию вручную:
  ```js
  // пример: подержать "вниз" 2 секунды
  game.input.keys = new Set(['KeyS']);
  for (let i=0;i<120;i++) game.unit.update(1/60, game.input, game.world);
  game.input.keys = new Set();
  ```
  Либо форсни кадр скриншотом (он будит цикл).
- **Окно превью иногда схлопывается в 1px** (глюк харнесса) — чини
  `preview_resize` (например 980×1000), затем `game.resize()`.
- `window.game` — точка входа в состояние для отладки.

Очаги невидимы в мире (в дебаге — ☢-маркер + кольцо). Эффект помех — `render_glitch.js`. |

| `unit.js` | `Unit` — движение, прерываемое бурение (копит `tile.dig`, порог через `digThreshold`), `hp`/`maxHp` (из корпуса). Энергии/расхода нет: модули дают абсолютные статы. Локомоция как у юнита: клинг к породе, гравитация (без опоры и снизу воздух — падает), копание настоящих тоннелей; в воздух — только при опоре назначения (в открытом пространстве ползёт к дальней стенке и копает там). | `upgrades.js` | `Upgrades` — внутрисессионные апгрейды (структура Dome Keeper), открываются на базе по **Пробелу** (`game` режим `upgrades`). Редактирование скелета идёт по СТАТИЧНОЙ позе (`editRig` — резолв с `noAnim`): ручки/драг не зависят от фазы анимации (иначе idle-свинг запекался в `ang` и нога «уезжала» со временем). Сегмент ищется по ДЕФ-индексу (`sg.idx`), т.к. `leg.segs` отсортирован по z (позиция в массиве ≠ порядок определения). **Ручки на канвасе** (выбрал сегмент — кликом ПРЯМО ПО НЕМУ на холсте `nearestLegSeg` ИЛИ по его `<b>` в панели; на стыках всех ног — слабые синие маркеры-подсказки): **синий КРУГ на стыке** тянет угол+длину (`ang`/`len`), **зелёный КВАДРАТ на корне** — пивот/выравнивание спрайта (`offX`/`offY` через обратный поворот; по умолчанию = корень, т.е. на ПРОТИВОположном конце кости от синего), колесо — масштаб спрайта сегмента. Кость между ними — пунктир (не хват). При выборе сегмента прочие точки (масс-детали/хаб/маркеры) ПРИГЛУШАЮТСЯ — ручки не путаются; хит-тест берёт ближайшую ручку (круг vs квадрат, разные формы). **Поворот СПРАЙТА** (отдельно от угла кости `ang`) — поле `пов°` или **Shift+колесо** (хранится в `PART_SPRITES.rot`/`PART_SPRITE_SRC.rot`, экспортится). `sw`=свинг сегмента (размах качания при ходьбе/idle: 0 жёстко, 1 полный, − противофаза). ## 5. Правила кода

- **Логика отдельно от рендера.** `update(dt, ...)` не должен зависеть от Canvas;
  `draw(...)` не меняет игровое состояние.
- **Ввод — по `e.code`** (`KeyW`/`ArrowUp`/…), не по `e.key`. Раскладко-независимо
  (на кириллице `e.key` ломается).
- **Главный цикл — rAF, `dt` в секундах, клампить** (`dt = min(dt, 0.05)`).
  Скорости/расходы — в `единицах/сек` или `/блок`, всегда умножать на `dt`.
- **Никаких магических чисел по коду.** Стартовые значения (из GDD) — в одном
  месте как именованные константы; их тюнят на плейтестах.
- **UI-тексты — по-русски.** Идентификаторы кода — латиницей/англ.
- **Комментарии — только ПОЧЕМУ** (неочевидный инвариант, причина), не ЧТО.
  По умолчанию комментариев нет.
- **Без преждевременных абстракций**, без мёртвого кода и полуреализаций.
  Не добавляй обработку невозможных кейсов.
- **Маленькие функции, явные имена**, без скрытых сайд-эффектов.
- Без сборки: классы — глобальные, общие через порядок `<script>`. Помни про это
  при добавлении файла (допиши тег в `index.html` в правильном порядке).
