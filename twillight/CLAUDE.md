## 1. Проект

**Twilight of the World (Сумерки мира)** — roguelite-копалка, вид сбоку, с
гравитацией. Игрок-ИИ через
базу-принтер управляет ботами-бурами: бот выходит на поверхность, копает вглубь,
добывает ресурс, возвращается. Дизайн-источник — `gdd_mvp_v0.3.md` (этап M0+).

**Стек:** чистый HTML + JS + Canvas 2D. **Без npm, без сборщиков, без фреймворков.**
Открывается двойным кликом по `index.html`. Главный цикл — `requestAnimationFrame`.

**Что уже есть:** тайловый мир со слоями/твёрдостью, юнит-Tachikoma (ход/лазанье/
гравитация/клинг к породе/авто-копание), энергия выводится из модульной сборки
(«ядро»), гекс-конструктор модулей, меню/пауза, сохранение лучших метрик в
localStorage.

## 2. Запуск и проверка

- **Запуск:** `index.html` двойным кликом, либо статик-сервер из
  `.claude/launch.json` (порт 8123).
- **После КАЖДОГО изменения проверяй в браузере** (preview): скриншот ключевых
  экранов + `preview_console_logs` (ошибок быть не должно).
- **rAF в превью тормозит** между «тихими» eval-вызовами (фоновая вкладка). Чтобы
  проверить логику детерминированно — шагай симуляцию вручную:
  ```js
  // пример: подержать "вниз" 2 секунды
  game.input.keys = new Set(['KeyS']);
  for (let i=0;i<120;i++) game.unit.update(1/60, game.input, game.world);
  game.input.keys = new Set();
  ```
  Либо форсни кадр скриншотом (он будит цикл).
- **Окно превью иногда схлопывается в 1px** (глюк харнесса) — чини
  `preview_resize` (например 980×1000), затем `game.resize()`.
- `window.game` — точка входа в состояние для отладки.

## 3. Файлы

| Файл | Ответственность |
|---|---|
| `index.html` | Разметка, canvas, **загрузчик скриптов** (массив имён → `document.write` с `?v=Date.now()` для cache-busting; порядок = порядок массива). |
| `style.css` | Полноэкранный canvas, тёмный фон. |
| `constants.js` | Общие константы мира/юнита, типы тайлов (`AIR/ROCK/BORDER/INDESTRUCT` — последний не копается), `isSolid`, `RESOURCE_DEFS` (железо/органика/кристалл: цвет, `tough`-множитель порога копания, `slots`), `digThreshold(t)`, `HULL_DEFS` (корпус: `radius` гекс-сетки, `hp`; резист даёт модуль «Кожух»), `HEAL_RATE`, `LOAD_PENALTY`/`SPEED_MIN_FRAC`. Закольцовка: `WORLD_W`, `wrapX`/`wrapPx`/`wrapDeltaPx`. Генерация: `CRUST_Y0/Y1`/`CRUST_HARD` (корка хлама), `VOID_SCALE`/`VOID_THRESHOLD` (пустоты), `OTHER_CITIES`/`CITY_MIN_GAP_X` (чужие города), `WILD_NESTS`/`WILD_HP` (дикие гнёзда). **Дизайн-система** (см. `design/`): `PAL` — тёплая тёмная палитра (10 нейтралей void→chalk + акценты gold/blood/toxic/amber/cobalt с `*Dim`/`*Bright`); `FONT_DISPLAY` (Tektur), `FONT_MONO` (JetBrains Mono), `FONT_BODY` (IBM Plex Sans Condensed). Новый UI-код берёт цвета/шрифты отсюда; «закон одного пигмента» — один акцент на элемент. |
| `save.js` | `SAVE_KEY`, `loadSave`/`writeSave` (localStorage). Хранит `bestDepth`, `runs`, `rep` (репутация по имени города, персист между сессиями). |
| `world.js` | `World(seed)` — карта, тайлы, слои, генерация из seed (разнообразие за сессию), туман войны (`seen`/`reveal`). Мир закольцован по X (тор): `tileAt/isSeen/reveal` wrap через `wrapX`, боковых границ нет (только дно). `rand` (mulberry32) — размещение пещер; `hash` (с seed) и `pnoise` (периодический value-noise, бесшовный по кольцу) — плотность зонами (`tile.dens`→`hardness`), пустоты (порог `VOID_THRESHOLD`), скверна `radAt`. Спецслои: корка спрессованного хлама `CRUST_Y0..Y1` (очень высокая плотность/твёрдость, барьер); неразрушимый фундамент (`INDESTRUCT`, `layFoundation`) только под самим городом (стартовый — под принтером+спавном; чужие — под маркером), остальной пол пещеры копается. Чужие города (дружественные): `genCaverns`→`this.caverns` (эллипс-пещеры, `name`/`rep` — задел под задания, фундамент под маркером). Дикие города-гнёзда: `genWilds`→`this.wilds` (глубже, `hp` для рейда, без фундамента; источники волн; копят `loot` от собирателей и `charge` от разведчиков). Размещение — `placeNest` (бэнды глубины ∝ `MAP_H`, разнос по тору 2D). `inCavern`/`inWild`/`inEllipseList`. Слои/радиация масштабируются с `MAP_H`. Карта 144×180 (тор по X). `tile.resource`/`resourceFor`. `setAir` ставит `tile.dug=true` (прорытый ход ≠ природная пустота — враги избегают своих ходов). Скверна — данные генерации/урона, в мире не рисуется (виджет «Кожух»). |
| `input.js` | `Input` — held-state по `e.code`. |
| `unit.js` | `Unit` — движение, прерываемое бурение (копит `tile.dig`, порог через `digThreshold`), энергия, `hp`/`maxHp` (из корпуса). Движение — только с ОПОРЫ (клинг к соседней породе): любой ход/лазанье/прыжок в воздух требует `anchored`, иначе действует гравитация — в свободном падении управление не действует (зажатые клавиши отделены от физики, «полетать» вбок нельзя). Подъём по «вверх»: явный «вверх+вбок» → диагональ на уступ; «вверх» в воздух с опорой наверху → лезет по шахте/стене (без приседа); если прямо вверх не зацепиться, но сбоку ЕДИНСТВЕННЫЙ уступ — авто-цепляние к нему (одной кнопкой «вверх»); и только настоящий прыжок в ОТКРЫТЫЙ воздух даёт присед `crouchT` (`JUMP_CROUCH_T`) + замедленный прыжок (`JUMP_SPEED_FRAC`) — ощущение веса. `anchoredAt` — только соседняя порода (искусственных полов нет); пол стартовой пещеры держится за гарантированный породный грунт под ним. `unit.dug` — событие «выкопан ресурсный тайл». `effectiveSpeed()` — ход с учётом веса груза (`unit.load`, выставляет game): движок-`moveSpeed` — абсолют без нагрузки, замедление `LOAD_PENALTY`/гекс до `SPEED_MIN_FRAC`. Урон скверны/лечение/смерть — в `game` (цикл). |
| `camera.js` | `Camera` — тороидальное следование (мир закольцован по X): `x` в `[0,WORLD_W)`, `follow` идёт кратчайшим путём через шов, `screenX(px)` даёт экранную X сущности (ближайшая копия по кольцу). По Y — клампы. |
| `city.js` | `City` — таймер гибернации города и кольца HP (= резервные источники энергии: основной реактор унёс игрок). Реактор города стоит в юните → вне базы город обесточивается; кольца гаснут снаружи внутрь (стадии: внешний контур → внутренний → ядро), обнуление всех → гибернация (`dead`) = обрыв связи ИИ↔юнит = конец игры. `damage(amount)` — высос/урон контура рейдером снаружи внутрь; пробитый контур теряется навсегда (на базе активный — дозаряжается). |
| `enemy.js` | `Enemy` — враг диких гнёзд. Локомоция как у юнита: клинг к породе, гравитация (без опоры и снизу воздух — падает), копание настоящих тоннелей; в воздух — только при опоре назначения (в открытом пространстве ползёт к дальней стенке и копает там). Поведение задаёт `game`: `seek` (блуждание flow-field `pnoise`+тяга вверх `UP_BIAS`, без знания целей) / `goto` цель (`return` в гнездо, `goresource`). `wanderDir` ключ `[вдоль-корки, посещён(recent), старый-ход(tile.dug), -heading, воздух]`: анти-петля (не кружит в полости), не топчет свои ходы (`tile.dug` ≠ природная пустота → роет НОВОЕ, расползание), РОЕТ к цели важнее хождения по пустотам, у корки роет СКВОЗЬ неё вверх (не вдоль). `homeR` (= размер каверны гнезда) — радиус «дома» для despawn (центр-воздух недостижим). Копатель **не подбирает ресурс**: роет как обычно, но прокопанная жила не пропадает — остаётся на месте лутом (`enemy.dug`→`game` зовёт `loot.spawn`). Типы: **копатель** (разведчик ищет города; радиус обнаружения — на город, покрывает каверну + запас), **собиратель** (1 ресурс) и **разведчик** (`raider`, фаза 5: `RAIDER_SPEED`=5, **НЕ копает**, лёгкий — **летит** по воздуху без гравитации/клинга; бежит по тоннелям копателей к базе, высасывает контур и несёт заряд `carry='charge'` домой — навигация/урон в `game`). `this.speed` per-type. |
| `render_enemy.js` | `drawEnemies` — дроны врагов: красный «глаз» (копатель) / зелёный (собиратель), бур по направлению, несомый ресурс над собирателем; `drawRaider` — разведчик: красный угловатый ромб с глазом, светящийся заряд энергии над ним при возврате (`e.carry`). |
| `cycle.js` | `Cycle` — внутренний таймер-фаза мира (`CYCLE_TIME`≈75с): макро-эскалация, тикает реальным временем в `playing`. Волны диких городов — будущие фазы (см. `design_cycles.md`). |
| `quest.js` | `Quest` — задание от города (1-й код-шаг, см. `design_meta.md §9`). Пока тип «поставка N ресурса»: `onDeliver(type)` копит прогресс при сдаче на базе, `checkDeadline(cycleN)` — провал по дедлайну в циклах. `makeQuest(cycleN)` — генератор (реже ресурс → меньше N). Начисление репутации (`save.rep`) и UI — в `game`/`hud`. |
| `intro.js` | `Intro` — заставка старта забега (таймер `INTRO_*`): печать корпуса → установка реактора → синхронизация. Пропуск — Пробел. |
| `loot.js` | `Drop` (выпавший ресурс/модуль: гравитация по тайлам) + `Loot` (`spawn` ресурса, `spawnModule` снятого модуля, `update`). Ресурс лежит `PICKUP_ARM` (1с) → подхват в радиусе `PICKUP_R`=1 (текущий тайл + соседние), втягивается за `SUCK_TIME` (≈0.55с): дроп едет от старта (`d.sx/sy`) к юниту (`d.ux/uy` — для рисовки лап-граберов). Дроп-модуль (`d.module`) подбирается так же → `inventory.tryInstall`. `update` возвращает true при установке (game рефрешит статы юнита). |
| `effects.js` | `Fx` — лёгкие визуальные частицы (логика, не влияет на игру). `burst(px,py,types)` — единицы ресурса вылетают из юнита вверх и тают (сдача груза). |
| `shield.js` | `RadWidget` — состояние виджета защиты от скверны: ядро, сфера-щит, налетающие частицы. Частота ∝ фону; `(rad−resist)/rad` — доля «пробоя» (частицы, доходящие до ядра = урон). |
| `inventory.js` | Гекс-математика, `MODULE_DEFS`, `Inventory` (сборка ядра: связность, статы, drag/выбор/поворот+wall-kick, рендер). `MODULE_DEFS` несут `removable` (реактор/двигатель — `false`, снять нельзя; бур не `required`, чтобы можно было выйти без него с подтверждением). Иконки/форма модулей — `drawModuleIcon`/`drawModulePiece`. Снятие на полку свободно (реактор/двигатель отскакивают назад). `tryInstall` — авто-переустановка подобранного модуля на свободный связный гекс. Модалка — НА ВЫХОДЕ (`needsExitConfirm`: нет бура или кожуха): `this.confirm` хранит callback выхода, `drawConfirm` (кнопки `confirmYes/No`). Корпус `this.hull` (`HULL_DEFS`) задаёт радиус гекс-сетки и `maxHp`; стойкость к скверне `radResist` суммируется с активных модулей «Кожух» (`MODULE_DEFS.casing`, kind `shield`). Груз: `cargo` — перетаскиваемые объекты-ресурсы (как модули): `where:'board'` (в гексе ядра) либо `'ground'` (на полке «Земля», вне ядра). Общий drag через `pieceById`/`pieceAt`/`occCells` (модули И груз не перекрываются); сброс мимо ядра → на полку. `addCargo` (первый свободный гекс), `deliverBoardCargo` (сдача — груз из ядра уходит, полка остаётся), `cargoFreeHexes`/`cargoTotalHexes`/`cargoCapacity`/`cargoUsed`/`cargoCounts`/`resetCargo`; `drawCargoPiece` рисует ресурс по силуэту. `boardLoad()` — вес для скорости (груз + СЪЁМНЫЕ модули; каркас не считается). Сводка `drawSummary` показывает «Скорость» = эффективная с учётом `boardLoad`. |
| `render_world.js` | `drawWorld` (порода-«кладка»: тёмный раствор + куски-булыжники размером ∝ плотности; неоднородное дно ходов; рваные края). Трещины по `tile.dig` — паутина на каждом осколке, проступает прогрессивно от стороны входа бура (соседний воздух) вглубь тайла. `raggedTeethRects` — зубцы рваного края, общие для видимой кромки (`raggedEdge`) и силуэта тени. `drawTunnelShadow` — длинная мягкая тень-«труба»: силуэт породы с рваным краем строится на оффскрине (зубцы вырезаются `destination-out`), затем `shadowBlur` внутрь хода (клип по воздуху) — тень идёт по неровной линии, а не по сетке. `drawBoreMarks`/`boreSide` — следы бура на стенках (дуги-борозды + блик), кроме природной пещеры города. `drawResourceVeins` — вкрапление жилы в породу кластером фигурок по типу (через `drawResourceCluster`, см. `render_resource.js`); центр сдвинут от сетки для органичности (туман сам притеняет невидимое/вне сканера). `drawCityMarkers`/`drawWildMarkers` — маркеры дружественных городов (ступенчатый + имя) и диких гнёзд (разрушенная масса + тлеющее красное ядро); в дебаге показываются без тумана. `INDESTRUCT` рисуется тёмной плитой-основанием (банты сверху/снизу), без осколков, но даёт силуэт тени. Рендер закольцован: диапазон X без клампа (lookups wrap), сущности/принтер — через `camera.screenX`. `drawFog` (туман войны + свет мягким градиентом; диапазон с запасом +1 тайл за вьюпортом — иначе у кромок мелькает порода). |
| `render_resource.js` | Единый язык форм ресурсов: `paintResource` (одна фигура по силуэту: железо — рвано-квадратный обломок с заклёпками/ребром; органика — округлая «клетка»; кристалл — ромб) и `drawResourceCluster` (кластер мелких фигурок для вкрапления в породу, как в Dome Keeper). Общий для жил/дропа/груза. |
| `render_module.js` | `drawModuleIcon` — монохромная иконка модуля; `drawModulePiece` — модуль как объект (его гекс-форма в цвете + иконка), общий ассет инвентаря и дропов, размер ∝ числу гексов. |
| `render_loot.js` | `drawLoot` — выпавшие ресурсы (`paintResource`, ~1 гекс) и снятые модули (`drawModulePiece`); свечение + сжатие при подборе; `drawGrabLegs` — две сегментные лапы от юнита к ресурсу при втягивании. |

PCB-пальцы; акцент по смыслу: gold/cobalt-data/toxic/blood) + `boltHead`/`edgeFingers`/`hazardTape`/`hazardTapeV`/`serialChip`/`pulseDot`(LED-мигание)/`drawStaticBg` (фон статичных экранов)/`drawCrtOverlay` (виньетка+скан-лайны) — внутриигровой HUD по дизайн-системе (`PAL`/`FONT_*`): бары HP(кровь)/энергии(янтарь), панель «Груз» (свободные/всего + по типам), виджет «Кожух» (`drawRadWidget` через `dbg.radWidget`), индикатор цикла; в дебаг-строке — текущая скорость юнита (`effectiveSpeed`, вместо fps). ## 4. Архитектура: один тип сущностей — один файл

Главное правило структуры. **Не наращивай `game.js` — выноси новую подсистему в
свой файл.** Раскладка уже соответствует этому (см. таблицу в разделе 3):
`constants`, `save`, `world`, `unit`, `camera`, `input`, `inventory`,
`render_world`, `render_unit`, `hud`, `ui_menu`, `game`.

Будущие файлы по мере роста (создавай по той же схеме):
- `physics.js` — гравитация/коллизии, если логика движения разрастётся (сейчас в `unit.js`).

> При следующей новой подсистеме — заводи отдельный файл, а не дописывай в `game.js`.

## 5. Правила кода

- **Логика отдельно от рендера.** `update(dt, ...)` не должен зависеть от Canvas;
  `draw(...)` не меняет игровое состояние.
- **Ввод — по `e.code`** (`KeyW`/`ArrowUp`/…), не по `e.key`. Раскладко-независимо
  (на кириллице `e.key` ломается).
- **Главный цикл — rAF, `dt` в секундах, клампить** (`dt = min(dt, 0.05)`).
  Скорости/расходы — в `единицах/сек` или `/блок`, всегда умножать на `dt`.
- **Никаких магических чисел по коду.** Стартовые значения (из GDD) — в одном
  месте как именованные константы; их тюнят на плейтестах.
- **UI-тексты — по-русски.** Идентификаторы кода — латиницей/англ.
- **Комментарии — только ПОЧЕМУ** (неочевидный инвариант, причина), не ЧТО.
  По умолчанию комментариев нет.
- **Без преждевременных абстракций**, без мёртвого кода и полуреализаций.
  Не добавляй обработку невозможных кейсов.
- **Маленькие функции, явные имена**, без скрытых сайд-эффектов.
- Без сборки: классы — глобальные, общие через порядок `<script>`. Помни про это
  при добавлении файла (допиши тег в `index.html` в правильном порядке).
