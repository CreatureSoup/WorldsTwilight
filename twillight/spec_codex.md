# spec_codex.md — База данных: кодекс, глоссарий, поток данных

> Код: `codex_dom.js`+`codex_dom.css` (DOM-оверлей), интеграция — `game.js`
> (updateServers / updateEnemyScan / updateBackdrops / checkDiscoveries), якорь — `SCAN_RING`.

## Экран «БАЗА ДАННЫХ» (DOM-оверлей)

- Порт `database/project/src/codex.jsx` на ваниллу 1:1 (как мета). `codexDomShow(game)` /
  `codexDomHide()` / `codexDomBack()` — `<div id="codexScreen">`; содержимое перерисовывается
  ЦЕЛИКОМ (`cxRender`) на каждое действие, события — делегированием (`cxClick`). Стиль —
  ацтекский «камень солнца» × киберпанк. Открытие: кнопка «База данных» в меню →
  `mode='database'` + `codexDomShow` (canvas под оверлеем тёмный). «← назад» (`#cxBack`) / ESC →
  `codexDomBack` → `mode='menu'`. ESC сначала закрывает модалку просмотра, потом экран (`_cxKey`).
- Кнопки «симуляция скана» НЕТ — фрагменты приходят только из игры.

## Вкладка ГЛОССАРИЙ

Журнал находок ИИ: `CXCATS` (серверы / дикие города / спящие города / вражеские юниты /
пещеры·культ.слой / останки роботов) + `CXENTRIES`. Слева список по категориям, справа карточка
(цикл/ИД/глубина + «ИНТЕРПРЕТАЦИЯ ИИ»-лор). **Показываются только НАЙДЕННЫЕ** записи
(`_cxFoundSet`; пустое состояние «Журнал пуст»). Открытие — при ПЕРВОЙ встрече объекта:
`codexDiscover(id)` / `codexDiscoverCat(cat)` из `game.discover`. `codexCatExhausted(cat)` —
категория исчерпана (game перестаёт опрашивать).

## Вкладка ВОССТАНОВЛЕНИЕ — мандала-диск

- `cxMandala(codex, pct, complete, selSeg, interactive, mini, size, anim)` — строка SVG:
  зубчатый венец-«мерлоны» (spin-rev), кольцо-греки (spin-slow), радиальные секторы
  (заполняются `frag/max`), внутреннее глиф-кольцо (меандры — ФИКС. сетка 16, кратная 4 цветным
  квадрант-дугам, НЕ по N секторов данных — иначе наползали на границы), центральный Тонатиу +
  счётчик %. Клик по сектору → его «поток данных» в сайдбаре.
- `anim`: `{segFrac:[…]}` (intro-заливка по очереди) ИЛИ `{growSeg,growFrac}` (рост одного
  сектора — попап) ИЛИ `{build:{center,seg,ring}}` (поэтапное проявление: три группы SVG
  оборачиваются `<g opacity scale-от-центра>`).
- **Intro-заливка по очереди** (вход на вкладку): непустые секторы заполняются один за другим
  (`cxSeqFracs` → `{segFrac}`; длительность ∝ числу секторов; `cxStartFill`/`cxTickFill` rAF
  перерисовывает ТОЛЬКО `#cxDisc`; активный сектор — `seg-pulse`; кольца-спины на время замирают).
- **Запечатывание** (`cxFinalize` при 100% → `_cxSeal`/`cxSealTick`): фаза A (~620мс) — диск
  «уезжает в слот» восстановленных (translate к сайдбару + scale↓ + fade), мини-диск с маркером
  `◆ НОВАЯ ЗАПИСЬ` появляется в списке; фаза B (~1300мс) — НОВЫЙ диск собирается ПО ЧАСТЯМ
  (`build`: центр+% → секторы → внешний венец, стаггер). Уход с вкладки/закрытие — мгновенное
  завершение. Кнопка «ЗАПЕЧАТАТЬ ДИСК» скрыта при `restored` (нет двойного триггера).
- Восстановленные диски — мини-мандалы; клик → модалка `cxViewerHTML` с видео-расшифровкой
  (`decrypt`-текст + слот под клип; видео — заглушка).

## Цепочка дисков и данные→%

`CODEX_DEFS` — **10 дисков** от простого к сложному; сегменты с РАЗНЫМ числом фрагментов
(`frags[]`, неравномерно → диски «рваные»); % = набрано/всего. Поздние диски КРУПНЕЕ (I 8 сег/24
фр, II 10/38, III 14/64 — прогрессия в самой геометрии). Диск открыт, когда предыдущий запечатан
(`_cxRelock`). Один источник данных = `CODEX_DATA_PER_SCAN`(=1) фрагмент; пещера-сцена =
`BACKDROP_DATA`(=2).

## Внутриигровой попап (фрагмент получен)

`codexGainData(n)` → текущий диск; если добавилось — `codexPopupShow(r, game._codexAnchor())`.
**НЕ модалка, БЕЗ рамки**: диск появляется РОВНО на месте HUD-кольца скана и того же размера
(якорь из `SCAN_RING`/`coordScale` → CSS right/bottom/size; `#codexPopup` z-55,
pointer-events:none). Фазы `cxPopTick`: (1) мигает завершённое кольцо скана (cobalt 100%) →
(2) схлопывание → (3) проявление диска (~200мс), затем ЛИНЕЙНО (не easeOut — изменение
«съедалось») растёт фрагмент + счётчик % тикает старое→новое (крупно под диском, без «+N»;
на смене цифры отбивка scale 1.34→1 за 150мс) → hold ~2.2с → последовательный fade: сперва диск,
потом % (opacity на детях). `disc._mode` гарантирует содержимое в любой фазе (фикс «пустого
диска» при позднем первом кадре rAF). Попап заменяет HUD-надпись «ДАННЫЕ ИЗВЛЕЧЕНЫ»
(`_scanDoneT=0`; если диск полон и попапа нет — обычная надпись 2.4с).

## Источники данных (game.js)

- **Серверы** (`updateServers`): ближайший откопанный недокачанный в `SCAN_RADIUS`; `data +=
  dt/SCAN_TIME` (уход — пауза, прогресс сохраняется); done → лог «НАЙДЕНЫ НОВЫЕ ДАННЫЕ»,
  `dataCount++`, фрагмент+попап. `activeScan` → лучи + HUD-кольцо.
- **Враги** (`updateEnemyScan`): то же по врагам, разово на юнита (`e.scan/scanned`) → лог
  «СКАНИРОВАН ВРАЖЕСКИЙ ЮНИТ», `discover('unit')`, фрагмент+попап. `scanEnemy` → лучи + кольцо.
- **Пещеры-сцены** (`updateBackdrops`): вход → свип `BACKDROP_SWEEP` → `_backdropDone`:
  `discover('cave')`, фрагменты+попап, лог.
- **Находки** (`checkDiscoveries`, тик ~5/сек): первая встреча сервера/гнезда/каверны/врага по
  `world.isSeen` → `discover(cat)` = глоссарий + лог + крупная подсказка (ОДНОРАЗОВО); отсечки
  высоты `HINT_DEPTHS` при подъёме. Оптимизация: пропуск исчерпанных категорий
  (`codexCatExhausted`), замеченных объектов (`o._noticed`), полное отключение `_discDone`.

## Персист

`save.codex = {frags, restored, found}` — `codexBindSave(save)` в конструкторе game;
`cxInitCodices` гидратит (с проверкой длины `frags[i]`); `cxPersist` на каждое изменение →
`writeSave`. Всё null-безопасно (`sv && sv.frags && …`).
