# spec_ui.md — UI: HUD, меню, сборка, апгрейды, интро, подсказки

> Код: `hud.js`, `ui_menu.js`, `render_city.js`, `inventory.js`, `upgrades.js`,
> `intro.js`/`render_intro.js`, `hints.js`/`render_hint.js`, навигация — `game.js`.
> Мета-экран и кодекс — `spec_meta.md` / `spec_codex.md`.

## Дизайн-система (constants.js, см. design/)

`PAL` — тёплая тёмная палитра: 10 нейтралей void→chalk + акценты gold/blood/toxic/amber/cobalt
(с `*Dim`/`*Bright`). Шрифты: `FONT_DISPLAY` Tektur (заголовки), `FONT_MONO` JetBrains Mono
(HUD/данные), `FONT_BODY` IBM Plex Sans Condensed (длинные тексты). **Закон одного пигмента —
один акцент на элемент.** Новый UI-код берёт цвета/шрифты ТОЛЬКО отсюда.

## Режимы игры (game.js)

`menu / inventory / intro / playing / upgrades / paused / gameover / progress / database`.
`progress`/`database` — DOM-оверлеи (canvas тёмный); выход — в оверлее. На gameover Enter →
`endRun` + `mode='menu'` (рисовка пропускается на этом кадре — иначе `drawWorld(null)` крашится).
**Дебаг-обзор (B)**: свободная камера, туман выкл, юнит заморожен, мир ЖИВЁТ; серверы/очаги/гнёзда
видны с метками.

## Меню-навигация (game.js)

`menuButtons()` по режиму: menu — `start`/`progress`/`database` (вертикальный список внизу-справа,
не перекрывает заголовок/директивы); paused — resume/restart/mainmenu; gameover — mainmenu.
`menuNav()`: WASD/стрелки двигают `menuSel` (с заворотом), Space/Enter — `doMenuAction` ВЫБРАННОЙ
кнопки (дублируют друг друга); мышь двигает тот же `menuSel` (mousemove), клик — `menuClick`.
`b.hover = (i===menuSel)`; смена режима сбрасывает `menuSel=0` (`_modePrev`).

## HUD (hud.js)

- Тулкит техно-рамок: `techPanel` (рамка+уголки+болты+шапка), `boltHead`/`edgeFingers`/
  `hazardTape(V)`/`serialChip`/`pulseDot`/`pulseSquare`/`drawStaticBg`/`drawCrtOverlay`, `hudBar`.
- Геометрия левого стека — `HUD_VX/VY/VW/VH` (ЮНИТ) + `HUD_GY/GH/BANK_GH` (ГРУЗ/БАНК); `hudLeftBottom(hasBank)`
  даёт якорь для виджетов ниже (радар). **Тумблер ресурса** — полноширинная строка ВНИЗУ плашки ПЕЧАТЬ
  (виден только при установленном принтере). Идиома ВКЛ/ВЫКЛ как у тумблера ПУТЬ (`drawNavToggle`): срез-угол
  пилюля, ЗАЛИТЫЙ глиф-бокс + акцент toxic когда ВКЛ («КОПИМ РЕСУРС»/chalk), КОНТУРНЫЙ глиф + бронза когда
  ВЫКЛ («СДАЁМ ГОРОДУ»/pewter). БЕЗ текста «клик» (сам вид пилюли = «это переключатель»). `drawCargoToggle(ctx,
  L.toggle, hoard)`, клик (флип) — `game.printClick`. В «КОПИМ» (`game.hoardCargo`) на базе ресурс НЕ сдаётся
  (копится под печать).
- **Подсказка действия у города:** при `atBase()` в playing — под капсулой таймера (x214, y56) пульсирует
  «⎵ ПРОБЕЛ — УЛУЧШЕНИЯ ГОРОДА». Открытие экрана апгрейдов гейтится `unit.state === IDLE` (юнит стоит) — чтобы
  СТАРТ движения / двойное нажатие AA·DD НЕ дёргали экран самопроизвольно; debounce-таймер не нужен.
- Боксы: статус юнита (HP/корпус, слой/глубина/скорость), «ГРУЗ» (счётчики по типам, used/cap),
  цикл (справа от капсулы города), **цели сессии** (`SESSION_GOALS` — 3 статичные директивы,
  `accent`-пигмент PAL + `short`) компактно справа под виджетом города (y≈70).
- **Извлечение данных** (`dbg.scan || dbg.scanDoneT>0`): крупное круговое прогресс-кольцо в правом
  нижнем углу (cobalt-дуга; по завершении — toxic «ДАННЫЕ ИЗВЛЕЧЕНЫ» на `scanDoneT` сек). Геометрия
  кольца — `SCAN_RING{dx,dy,r}` (design-коорд.) — ОБЩИЙ ЯКОРЬ с попапом кодекса (диск встаёт ровно
  на место кольца).
- **Лог событий — всегда виден** (под кольцом): `// ЛОГ СОБЫТИЙ` + последние 3 записи
  `Ц<цикл> · <текст>` либо «— нет событий —». Пишется `game.logEvent` (макс. 16).
- **Тумблер «ОБНАРУЖЕНИЕ УГРОЗ»** (`drawAlertToggle`, левый столбец под «ГРУЗ») — ВКЛ/ВЫКЛ голо-маркеров
  (враги + нестабильности породы) + счётчик враждебных юнитов. Виден ТОЛЬКО при владении узлом меты
  `mast_sa`. Переключение — клавиша `V` или клик (`game.alertClick`/`alertHudRect`). Детали эффекта —
  `spec_enemies.md` → «Обнаружение угроз».
- **«ДЕТЕКТОР ЗАГРЯЗНЕНИЯ»** (`drawRadarCompass`, render_radar.js; левый столбец под тумблером угроз /
  под «ГРУЗ») — виден при `game._contamActive()` (СВОЙСТВО СКАНЕРА: `metaHas('mast_sr') && scanR>0`, НЕ
  модуль). Дизайн «**Гейгер-ветер**» кибер-ацтек: techPanel toxic + hazardV + линза-сонце, лучи-корона
  «разгораются» с интенсивностью загрязнения (вместо бара), морось влетает со стороны очага в ядро-глиф,
  внутренняя дуга-пеленг (отступ от обода) — сторона; вне очагов — «снежная» рябь + «СКАН ФОНА».
  Состояние/частицы — `RadarCompass` (radar.js), детали — `spec_world.md`.
- **ПАНЕЛЬ АКТИВНЫХ ДЕЙСТВИЙ** (`drawActionBar`, render_actionbar.js; ВНИЗ-ЦЕНТРУ, над строкой подсказок
  управления) — дубль хоткеев активных модулей кнопками: открываемость + игра мышью. По кнопке на действие
  (`game._actionList()` по `unit.stats`: impulse/screw=Пробел, radar/echo=1, hack=2). Кнопка — квадрат
  дизайн-системы (тёмная плита + уголки `_panelCorners` + 1px рамка), простой процедурный глиф в акценте,
  МЕЛКИЙ хоткей сверху (`keyLabel`). Состояния: норма (бронза/кость) · ховер/нажатие/АКТИВНО (акцент + рамка).
  **ЗАЛИВКА ВСЕЙ иконки снизу-вверх** (`d.fill(g)` 0..1) показывает заряд/готовность: радар/эхо = перезарядка
  (`1−cd/cdMax`, полна = готов), импульс/взлом = прогресс заряда/канала, винт = 1 пока щиты в ходу. ⚠️ Заменяет
  отдельный виджет кулдауна (`drawScanCooldown` ОТКЛЮЧЁН в `game.drawScene`, код оставлен — см. `render_scanners`).
  Клик/удержание инжектит хоткей в `input` (логика — `actionbar.js`), клавиатура и мышь делают одно и то же. Печать —
  НЕ здесь (свой режим/панель). Пусто → панель скрыта. Гейт: только playing (не печать/дебаг).

## Виджет города (render_city.js)

Hibernation Widget — ВЕСЬ статус города в одной капсуле 360×44 со скошенными углами (x=210).
Слева эмблема (3 кольца контуров + общий HP, цвет по фазе); в центре — надпись фазы + сегментный
бар; справа — крупный таймер «сек.МС» (`FONT_DISPLAY`, glow по опасности; таймер >100с → три
цифры, сотые скрыты, подпись СЕК). Фазы: `charging` ПОДПИТКА ГОРОДА / `full` ГОРОД ЗАПИТАН (toxic);
вне базы >30с ДО ГИБЕРНАЦИИ (amber) / 15–30с ВЕРНИСЬ К ПРИНТЕРУ (gold) / ≤15с СРОЧНО НА БАЗУ
(bloodBright+glow); `dying-*` — стадии шатдауна контуров (мигание 200мс, число = отсчёт до потери
контура, бар = HP кольца). Смена надписи анимирована (`_drawBarText`, easeInOutCubic ~360мс,
старая вверх / новая снизу). Скретч-состояние `city._bar*` — на самом city.

## Экран сборки (inventory.js)

- Открывается ТОЛЬКО перед забегом; в забеге модули не снимаются. Дефолтный корпус `core` (кольцо).
- **«← назад»** — лаконичная стрелка в рамке со скошенным углом (canvas-аналог `.mt-back`/`.cx-back`)
  в левом верхнем углу; клик → `onBack` (game: в меню до забега / в игру на лету — как ESC).
- Масштаб превью: `blueprintScale` множитель **1.22** (крупно, но модули/бур не режутся кромкой;
  1.55 обрезал верх). Лимит — `min(b.w, b.h-30)`: в ВЫСОКОМ окне масштаб берётся по ШИРИНЕ → юнит
  мельче высоты.
- **НИЗ композиции привязан к нижней кромке** (`_drawBlueprint` пересчитывает `blueprint.cy`):
  кончики ног уходят на `TILE*0.5` ЗА нижний клип — вся сцена (юнит+ноги+пол) едет вместе, уровень
  пола ОТНОСИТЕЛЬНО юнита не меняется. Фикс. доля высоты (старый `cy = mid + 6%`) оставляла снизу
  пустоту в высоком окне (масштаб по ширине). Привязка — по СТАБИЛЬНОМУ `_plLegDrop` (кэш вылета ног
  вниз, `design_legs.md` «Превью»), НЕ по мгновенному max точек ног — иначе `cy` гулял бы по кадрам
  (шаги/«дыхание») и юнит подпрыгивал. `cy` из `computeLayout` — дефолт для FK-фолбэка/первого кадра.
- Слева — живой превью собранного юнита: тот же риг/спрайты, что в игре; для кольца — IK-щупальца
  на фейковом полу (`_previewLegRig`; детали и анти-дрожь — `design_legs.md`, раздел «Превью»).
  Гнёзда-кольца (`SLOT_META`) наложены на реальные детали: установлен — cobalt, пуст — пунктир amber.
- **Выноски ПОВЕРХ юнита** (`_drawCallout`, рисуются ПОСЛЕ рига): тёмный чип с НАЗВАНИЕМ установленного
  модуля (цвет рамки = `MODULE_DEFS.color`) + линия от гнезда. Чип КЛАМПИТСЯ внутрь панели (`b`), чтобы
  длинные имена («РЕМОНТНЫЙ ТРЮМ») не обрезались кромкой. Пустой опц. слот (нет модуля) → «МОДУЛЬ НЕ
  УСТАНОВЛЕН» (приглушённо, рамка `PAL.bronze`). Направление выноски — `SLOT_META[cat].lx/ly`: у `aux`
  уведена ВЛЕВО-ВВЕРХ (деталь в кольце низко), чтобы чип не лез на деталь ТРЮМ-а; у `scanner` —
  ВПРАВО-ВВЕРХ, чтобы не лезть на пустой круг доп-слота (тот вверху-слева).
- **Позиции гнёзд (`computeSlots`)**: для КОЛЬЦА считаются по раскладке `def.parts` `ang`/`rad`
  (+`bodyOff` щупалец, как `drawRingUnit`), НЕ из `resolveUnitRig().parts` — у кольца там NaN. Для FK — из `rig.parts`.
- **Двигатель НЕ показываем** на сборке (`SLOT_META` без `engine`, галерея пропускает `engine`) — это
  ПАРАМЕТР КОРПУСА: модуль остаётся в `modules` (стат `moveSpeed` живой, сборка valid), но без слота/выноски/карточки.
- **Установка модуля — КЛИКОМ по карточке** (`pointerDown` → `modules[cat]=type`). **Перетаскивание
  ЗАКОММЕНТИРОВАНО** (`drag`/`pointerUp`/`_drawSlotPing`/`_drawDragGhost` — оставлены для ре-энейбла).
- Справа — вертикальный стек категорий, в каждой ГОРИЗОНТАЛЬНАЯ галерея карточек (спрайт варианта
  `mod:<id>` → деталь категории → иконка; имя+стат; «✓ УСТАНОВЛЕН» = выбранный); скролл колесом. Клик = установка.
- **Мульти-варианты слота**: `MODULE_DEFS` — реестр (ключ=id, `category`=слот); галерея берёт ВСЕ
  модули категории, гейтнутые `unlock` (id узла меты) — только при `metaHas`. Дефолт `defaultBuild` —
  первый НЕзагейченный. Смена — кликом. Пример: слот ТРЮМ = `cargo` (станд., ёмк 5) ИЛИ **`cargo_repair`**
  (ёмк 3 + `healRate` 1 HP/10с, `unlock:'mast_rep'`). Стат `healRate` → реген HP в `game` (playing,
  `healRate/10·dt`, на базе и вне). (Детектор загрязнения — НЕ модуль, а свойство сканера, см. выше.)
- **ДОП-СЛОТ (`aux`) — ОПЦИОНАЛЬНЫЙ слот** (`HULL_DEFS.optional:['aux']`): НЕ требуется для `valid`,
  `defaultBuild` его НЕ заполняет. Показывается (галерея/гнездо/выноска) только когда **открыт узлом `mast_hub`**
  И есть доступный aux-модуль ИЛИ установлен (`_categoryActive` гейтит на `metaHas('mast_hub')`; `loadBuild` тоже не
  восстановит aux-модуль без узла — нет утечки статов из скрытого слота). Клик по карточке опц. слота — ТОГГЛ (повторный = снять).
  Сейчас в нём модуль `shield` «Экран помех» (`category:'aux'`, `noiseResist` 0.4, `unlock:'mast_sh'`) →
  реген-эффект `game` (`max(0, radLevel − noiseResist)`); трек ЭКРАН ПОМЕХ докручивает. Будущие артефакты — сюда же.
- **Трек ремонт-трюма**: при экипировке `cargo_repair` (`s.healRate>0`) трек ЁМКОСТЬ ПРЯЧЕТСЯ, вместо
  него **РЕМОНТНЫЙ ТРЮМ** (`apply(s,lvl)`: +1 HP/10с И +1 ёмкость за уровень; cap 4 → макс 5 HP / 7 ёмк).
- **По умолчанию — сборка ПРОШЛОГО ЗАБЕГА** (`save.build={hull,modules}`): `bindSave`(в конструкторе game,
  после loadSave+metaBindSave)→`loadBuild` восстанавливает; `saveBuild` пишет на старте забега (`doInventoryStart`);
  `reset` между забегами тоже `loadBuild` (не сбрасывает в дефолт). Невалидный/закрытый модуль откатывается к
  `defaultBuild` (первый незагейченный модуль категории). `getStats().valid` = все слоты заняты. `getStats()`:
  `maxHp` из корпуса; `moveSpeed/digMult/scanR/capacity` из модулей.
- Груз: `cargo{iron,organic,crystal}`, `addCargo/cargoUsed/cargoCapacity/deliverOneCargo/
  resetCargo`. `cargoCapacity()` = `unit.stats.capacity`, если задан `inventory.unit` (ставится в
  `startSession`), иначе `getStats().capacity` (экран сборки). Новый стат: добавить в
  `MODULE_DEFS`/`getStats` + `UPG_TRACKS`, потребитель читает `unit.stats.X` — больше ничего.

## Апгрейды сессии (upgrades.js)

- Структура Dome Keeper: открываются НА БАЗЕ по Пробелу (`mode='upgrades'`). Валюта — банк сданных
  ресурсов (`bank`, копится в `deliverCargo`, обнуляется за забег).
- **Потолки гейтит узел «Инженерный допуск» (`mast_hub`):** БЕЗ него `trCap`→**1** для всех треков; с ним — штатные `cap`
  (СИЛА БУРА 3, ПРОЧНОСТЬ / ЁМКОСТЬ / СЕНСОР 2; узлы `metaCap` поднимают дальше). (ДОП-СЛОТ открывает `core`.)
  **Рисуем только реально достижимые слоты** (`nCells = trCap(tr)` — учитывает гейт «Инженерный допуск»: без узла 1 ячейка):
  база + открываемые узлом меты слоты (между `cap` и `metaCap.cap` → «ЗАКРЫТО · СЕТЬ ПАМЯТИ»). За ними
  ячеек НЕТ (инертного «—» больше не рисуем). Ширина ячейки ФИКСИРОВАННАЯ (как при полной `UPG_MAX`-сетке),
  поэтому короткие треки просто короче; подсветка выбранного ряда обрезается по `rowRight` (без пустого хвоста).
- **Мета-гейты/кап-лифты** (`metaNeed`/`metaCap` → `metaHas` на старте сессии, см. `spec_meta.md`):
  раздел ГОРОД («батареи»→timerMax; 3 контура→HP кольца) — за `core`; без него вместо секции —
  строка «// ГОРОД — ЗАКРЫТО · ТРЕБУЕТ УЗЕЛ «ЯДРО ИИ»». СИЛА БУРА cap 3→5 (`mast_drill`),
  ПРОЧНОСТЬ 2→4 (`mast_hull` Ремонтный цех); РЕМОНТНЫЙ ТРЮМ-модуль (`mast_rep`); ПРОЖЕКТОР (`mast_sens`),
  ЭКРАН ПОМЕХ (`mast_sh`, `cap:3` → макс 85%) — появляются от узлов.
  Раздел ГОРОД (жёлтая ветка `amb`) — 5 треков, каждый гейтнут СВОИМ узлом ветки (батареи/контуры
  ПЕРЕНЕСЕНЫ с `core`): **ЁМКОСТЬ БАТАРЕЙ** (`battery`→`amb_batt`, timerMax), **СУПЕР-ЧАРДЖЕР**
  (`charge`→`amb_charge`, `cap:3`, `city.recharge` 15→39 с/с), **КОНТУРЫ** (`contours`→`amb_cont`,
  `cap:3` — 3-в-1, fmt по очереди «ВНЕШ./ВНУТР./ЯДРО +80», распределение `cityRingBonuses`),
  **АВТО-ПОЧИНКА** (`cityrepair`→`amb_regen`, `cap:3`, охват колец → `city.repairLvl`), **РЕМОНТНЫЙ ДОК**
  (`dock`→`amb_dock`, `cap:4`, лечит юнит на базе → `cityDockRate`). Эффекты — `city.js`/`game.js`, см.
  `spec_enemies.md`. Раздел ЗАКРЫТ (нет ни одного трека) → строка «// ГОРОД — ОТКРОЙ ВЕТКУ ГОРОД».
  HUD во время вылазки: панель «// БАНК ГОРОДА» (сданные ресурсы) при `metaHas('amb_hub')` (`hud.js`).
  Трек ПРИВОД (moveSpeed) гейтнут несуществующим `u_engine` → скрыт (см. открытый вопрос в spec_meta).
- Гаджеты (`UPG_GADGETS`: магнит/ремонт/пинг) — легаси: в UI экрана НЕ рисуются (раздать по
  веткам меты при проработке).
- Цены `UPG_TIER_COSTS` (5 тиров). **Покупка — УДЕРЖАНИЕ** (`UPG_HOLD_TIME`≈0.55с):
  Пробел на выбранном треке или ЛКМ на карточке → заливка снизу вверх (`holdFrac`) → `buyTrack`;
  отпускание/смена выбора отменяет (`beginHold/endHold/tickHold`). Мышь: `pointerDown` выбирает
  трек + стартует hold; `buttons` — hit-rects карточек.
- **Скролл:** колесо/свайп (`onWheel`) двигают весь список. Авто-доводка к выбранному ряду —
  ТОЛЬКО при смене выбора WASD (`moveSel` ставит `_followSel`, draw применяет разово и гасит). Колесо
  сбрасывает `_followSel` → ручной скролл НЕ перебивается (раньше доводка срабатывала каждый кадр и
  возвращала экран к выбранному ряду, если он высоко — колесом было не уехать вниз).
- `buyTrack`/`buyGadget` → `spend(bank)` + `onChange(kind,id)` → game пересобирает
  `unit.setStats(applyToStats())` и `city.applyUpgrades(...)` — ЕДИНЫЙ путь статов.
- Сдача груза: по ОДНОЙ единице каждые `DELIVER_INTERVAL`=0.35с при `atBase()` И НЕ `game.hoardCargo`
  (тумблер «КОПИТЬ» блокирует сдачу — копим в трюме, напр. под печать структур); сданная единица копит банк.

## Интро забега (intro.js / render_intro.js)

`Intro` — таймер фаз `INTRO_PRINT` (печать корпуса: заливка снизу вверх + сканлайн) →
`INTRO_REACTOR` (влёт реактора из принтера, вспышка) → `INTRO_SETTLE` (синхронизация). Пропуск —
Пробел. Кольцо рисуется как в игре (`drawTentacles` ПОД + `drawRingUnit`); реактор ВЫКЛ до
установки (`unit.reactorOn` по фазе; в `playing` → true); `updateTentacles` зовётся в интро
(живые ноги). Плейсхолдер-прямоугольник принтера УБРАН — базу рисует ассет города; коорд.
`PRINTER` нужны для печати/реактора/`atBase`.

## Крупные подсказки (hints.js / render_hint.js)

`Hints` — ОДНА подсказка за раз (`show(text)`, `HINT_DUR`=2.8с + `HINT_FADE`).
`drawBigHint` — очень крупный короткий текст (~⅓ высоты, авто-ужатие), полупрозрачный, по центру;

`HINT_DEPTHS` (y 88/60/30/8 → ВВЕРХ / СЛЕДЫ ЛЮДЕЙ / РУИНЫ / ПОВЕРХНОСТЬ — директива «зерно
истины»), телеграф копателя «ПРОРЫВ К БАЗЕ». Гейт playing/!debug.

## Главное меню / gameover (ui_menu.js)

`drawMainMenu` — заголовок, сюжетный текст, `drawDirectives` (директивы `SESSION_GOALS` крупно),
кнопки списком внизу-справа; `drawPauseMenu`; `drawGameOver` — экран мета-пересчёта
(см. `spec_meta.md`). `wrapText` возвращает Y последней строки. `drawButtons` — общий рендер
кнопок с hover.
